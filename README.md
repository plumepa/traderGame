# PIXEL TRADER · 像素股神

一款运行在**微信小游戏**平台上的复古像素风股票交易模拟游戏。

> 营业部门口排起长队。你没做过功课，只揣着一万块钱挤进人群。
> 没人告诉你这是哪一年，也没人告诉你接下来会怎样 —— 自己看盘，自己判断。

---

## 玩法一句话

**一关 = 一段"年景"：随机抽 3 只不同行业的股票 + 专属新闻组，12 个月 = 12 个回合，每月看一条新闻，买卖股票，然后看着机构给你的持仓打分。打完一关可以继续下一关（钱带过去），也可以收手结算。**

- 起始资金 ¥10,000，**没有硬性通关目标 —— 赚得越多越好**
- **每关随机抽 3 只股票**（**行业互不重复**），从 36 只的池子里抽（12 个行业 × 3 只）
- **不告诉玩家这是哪一年、什么市场** —— 年份与牛熊对玩家完全隐藏，只能从盘面自己判断
- **连闯**：一关结束可选「进入下一关」（**资金延续上一关期末资产**）或「返回主界面」
- **每 5 关为一轮**，轮末可选「继续 · 再来五关」或「退市结算」（汇总整轮战绩）
- **跨关不重复**：轮界补货规则保证**连闯 10 关都不会看到重复股票**（见 §6b）
- 股票名与代码**全部虚构**（`9xxxxx` 段），避免与真实 A 股挂钩、也防止玩家"背答案"
- 新闻按板块匹配，且存在**板块错配**陷阱（见下）
- 每关交易满 12 个月到期结算，**年末按市价强制平仓**，按最终收益给出结局
- 每回合末插播一条新闻，其中有**假消息**
- 三家机构会为每只股票给出评级——评级方向**可能**暗示了消息真假
- **总资产**（现金 + 持仓市值）低于「最便宜一股的 100 股价钱」即宣告破产
- 熊市年景里，**有股票会退市爆雷**，持仓被强制清算

### 六种市场风格（玩家看不到，只在内部区分）

| 风格 | 中枢月偏 | 月波动 | 退市基准 | 定位 |
|---|---|---|---|---|
| `bull` 大牛 | +2.0 | 3.4 | 0.05 | 鸡犬升天，长期持有有正期望 |
| `smallBull` 小牛 | +1.0 | 2.2 | 0.03 | 温和修复、结构行情 |
| `flat` 震荡 | +1.4 | 3.6 | 0.18 | 没有趋势，靠波动制造机会与陷阱 |
| `calmFlat` 平静 | +0.15 | 1.1 | 0.10 | 横盘无量，最容易"手快必亏" |
| `smallBear` 小熊 | −1.4 | 2.6 | 0.22 | 阴跌磨底，反弹诱多 |
| `bear` 大熊 | −3.0 | 3.6 | 0.55 | 杀跌凶狠，退市频发 |

实测退市率（每风格 2000 局）：大熊 95.5% ＞ 小熊 62.9% ＞ 震荡 40.5% ＞ 平静 22.9% ＞ 大牛 13.6% ＞ 小牛 8.8%。

> **为什么要隐藏年景**：一旦标出「1996 全民炒股」，玩家就不用看盘了 —— 直接背答案
> （知道是牛市就无脑满仓，知道是熊市就空仓）。本作的核心乐趣是
> **「从价格与新闻里自己判断市场性质」**，所以年份只能是内部编号。
> `tools/diag-levels.mjs` 会守着这条：玩家的可见文案里不得出现年份或市场风格词。

> **年景层（`js/data/seasons/index.js`）现在只服务于"受控实验"**。
> 连闯要求"可以一直打下去、且跨关不重样"，而 20 个年景 × 3 只 = 60 个股票位、
> 36 只股票必然重叠（实测贪心选年景最多只能排出 ~7 关不重样），
> 所以默认路径改成了 `composeFreshLevel()` —— 直接从股票池抽。
> 显式传 `{ season }` 时仍走年景路径，`diag-rating` / `diag-styles` 靠它做受控实验。

### 三种新闻陷阱（本作核心玩法）

玩家明确要求的"不要一眼看穿利好利空"，落到三种新闻类型上：

| 类型 | 场景 | 对股价的影响 |
|---|---|---|
| **相关**（relevant） | 新闻板块 = 持仓股票板块 | 按 `truth` 生效：真消息照常、假消息反向 |
| **错配·无关**（irrelevant） | 「船舶运输利好」但你的股票主营**陆运** | **完全无效** —— 消息是真的，但跟你没关系 |
| **利好但承压**（pressured） | 新闻是利好，公司业绩却依然疲软 | **股价照跌** —— 利好出尽，筹码松动 |

> 玩家原话：「假新闻也可以是船舶运输的利好，但是股票是主营陆运的所以无关，
> 也可能是虽然有利好但是业绩依然承压」——这三类就是按这句话实现的。

### 四种结局

| 结局 | 触发条件 |
|---|---|
| **这 一 年 赚 了** | 到期结算时资产高于本金 |
| **这 一 年 亏 了** | 到期结算时资产不高于本金 |
| **宣 告 破 产** | 中途总资产低于「最便宜股价 × 100」，提前出局 |
| **退 市 · 满 载 而 归 / 割 肉 离 场** | 玩家在轮末主动收手，按整轮累计盈亏判定 |

## 平台约束（重要，三条）

微信小游戏有三个会直接导致**白屏报错**或**功能失效**的限制：

### 1. 无法读取项目源码目录

`wx.getFileSystemManager()` 只能操作用户数据目录，**不能 `readdir` 打包进来的 `js/data/`**。

→ 因此**不使用目录扫描**，而是在 `js/data/index.js` 中**显式注册**每一个数据文件。新增实体后必须补一行 import。

### 2. 不能 `import` JSON 文件

打包器会把 `'./stocks/900101.json'` 当作模块名，并自动补 `.js` 后缀去找 `900101.json.js`，报错：

```
Error: MiniProgramError
module 'js/data/stocks/900101.json.js' is not defined, require args is './stocks/900101.json'
```

→ 因此**所有数据文件都是 `.js` 模块**，用 `export default {...}` 导出：

```js
// js/data/stocks/900101.js
export default { code: '900101', name: '赤河酒业', /* ... */ };

// js/data/index.js
import stock900101 from './stocks/900101';   // 不带 .json
```

> `game.json` / `project.config.json` 是**平台配置文件**，必须保持 JSON —— 它们由工具直接读取，不走模块系统。

### 3. 小程序图表库一个都用不了（ECharts / wx-charts 都不行）

常见建议是「用 ECharts for Weixin（`ec-canvas`）或 `wx-charts`」。**这两个在小游戏里都跑不起来**，
因为它们是**小程序**生态的库，而小游戏移除了 BOM 与 DOM：没有 WXML、没有 `<canvas>` 组件、
没有自定义组件系统。

实测证据（拉取官方仓库源码逐项核对）：

| 库 | 致命依赖 | 实测 |
| --- | --- | --- |
| **ECharts for Weixin** | `ec-canvas.wxml` + `ec-canvas.json` 里 `"component": true` | 是**自定义组件**，JS 里用 `Component()` / `properties` / `methods` / `wx.createSelectorQuery` / `wx.createCanvasContext`。小游戏没有组件系统，直接无法加载 |
| **wx-charts** | `wx.createCanvasContext(canvasId)` | dist 里出现 1 次且是 context 的**唯一来源**（该 API 靠 canvasId 字符串绑定 WXML 组件，是小程序独有）；另有 `setFillStyle` ×24、`setStrokeStyle` ×12、`.draw()` ×1 等旧版异步 API |

两者都**只接受 canvasId 字符串**，没有「注入现成 context」的入口，因此无法改成小游戏用法。

→ 结论：**自己用标准 Canvas 2D API 画**，即 `js/styles/chart.js`（零依赖，约 250 行）。
它提供 `arrowLine()` / `lineChart()` / `chartLegend()`，支持坐标轴、网格、刻度、多序列、末端箭头、生长动画。

## 核心设计决策

### 0. 四次数据层重构（为什么现在长这样）

| 版本 | 数据组织 | 问题 |
|---|---|---|
| **v1** | 每关写死 3 只股票 + 72 条新闻，一个文件一实体 | 换关卡就得重写全部新闻；股票只有 3 只，玩一遍就腻 |
| **v2** | 熊市关卡再写一套 `bl_*.js` | 数据爆炸：每加一关就要写一套股票+新闻 |
| **v3** | 共享股票池 + 板块匹配新闻池 + 每局随机编排 | 用真实股票（茅台/宁德…）会让玩家"背答案"；只有 3 种市场风格太单调；3 关太少 |
| **v4（当前）** | **年景层** + 6 种风格 + 34 只虚构股 + 5 关 + 跨关不重复 | —— |

v3 的核心洞察：**新闻不该绑定到"某只股票"，而该绑定到"某个板块"**。
一旦新闻按 `sector` 标注，同一批新闻就能服务**任意随机组合**的三只股票 ——
于是「每关随机选股」和「新闻按选中的股票抽取」可以同时成立。

v4 把「随机」再往前推了一层，引入**年景（season）**这个中间层：

```
年景 = { 风格, 3 只股票, 6 条专属新闻, 内部叙事 }
```

一关 = 一个年景。好处是**"随机"与"策展"可以兼得**：

- 每关都是随机抽的年景 → 重玩不腻
- 但一个年景内部，3 只股票与 6 条新闻是**精心配好的**（行业互不重复、
  每只股票至少有一条对口新闻）→ 每个年景都像一个"写好的小剧本"，不是纯随机拼盘
- 年景池 20 个 × 一局 5 关 → **连玩 4 轮（20 关）都不会重样**

### 1. 股票池（`js/data/pool.js`）

**34 只虚构股票、12 个行业**，每只只存"性格"，**不存路径**：

```js
{
  code: '900101', name: '赤河酒业', sector: 'liquor',
  basePrice: 28, floor: 8,
  profile: { trend: 0.75, vol: 0.9, luck: 0.5 },
  personality: '白酒龙头：品牌力强，涨价能力突出，但估值敏感',
}
```

| 字段 | 含义 |
|---|---|
| `sector` | 行业大类，**新闻按此匹配**（不是按 code） |
| `profile.trend` | 趋势倾向 −0.8（强空）~ +0.8（强多） |
| `profile.vol` | 波动强度 0~2 |
| `profile.luck` | 命运倾向 −1（易爆雷）~ +1（易走强），影响极端事件与退市概率 |

**为什么全部虚构**：

1. **避免麻烦** —— 不想与真实上市公司、真实历史行情产生任何关联。
2. **防止玩家"背答案"** —— 看到"贵州茅台"就知道是好公司，游戏立刻失去判断乐趣。
3. 代码统一用 `9xxxxx` 段（`900101`…`901202`），并有一条断言守着
   `!/^(600|601|603|605|000|001|002|300|301|688)/`，**绝不允许与真实 A 股号段碰撞**。

行业分布（12 个）：白酒 ×3 / 地产 ×3 / 新能源 ×3 / 能源 ×3 / 科技 ×3 / 运输 ×3 /
金融 ×3 / 医药 ×3 / 消费 ×3 / 材料 ×3 / 农业 ×2 / 传媒 ×2。

> ⚠️ **`basePrice` 必须与 `luck` 不相关** —— 这一条被写错过**三次**，见 §1b。

#### 1b. ⚠️ 三次被推翻的统计判据（这是本项目最有价值的一段教训）

目标是「让"挑最贵的买"不构成优势」。我为此换了**三套判据**，前两套都是错的：

**判据一（错）：`corr(basePrice, trend) ≈ 0`**

看起来天经地义 —— 价格不该携带未来收益的信息。但**价格档位天然与趋势相关**：
贵股本来就是长期走强的结果。优化器为了把这个相关系数压到 0，
给出了荒谬的定价（地产 28 元、电力 4 元），反而破坏了常识。
**错误根源：把"因果"和"结果"搞反了 —— 相关本身不是问题，问题是"贵就一定好"。**

**判据二（错）：`买最贵的年化优势 < 0.5%`**

0.5% 这个阈值是我拍的，**没有任何统计依据**。

**判据三（错）：拿"均值差"去比"单路径 σ"**

实测 σ_path ≈ **48%**，看起来任何均值差都淹没在噪声里。但真正该比的不是 σ，
而是**均值自身的标准误 SE = σ/√N**（N=720 时 SE ≈ 1.81%）。
两者差了一个数量级 —— 用 σ 比，什么效应都"不显著"。

**正解：排列检验（permutation test）**

不做任何分布假设，也不需要拍阈值：

1. 把 34 个价格标签**随机重排** 40 次
2. 每次重排都算一遍"买最贵"的优势 → 得到一条**零分布**
3. 看真实分配的优势落在零分布的哪个百分位

实测：真实优势 **1.42%/年**，落在 `[−7.34%, +5.89%]` 零分布的**第 63 百分位** ——
**与随机分配无法区分**。这才是"价格不是信号"的严格说法。

> **通用教训**：当你想证明"某个效应不存在"时，不要拍一个阈值，
> 也不要拿 σ 当尺子 —— 去做**排列检验**。它不需要任何分布假设，
> 结论是"与随机无法区分"而不是"小于某个我编出来的数"。

#### 1c. ⚠️ 真正的缺陷不在相关系数，而在 `luck` 与价格的隐藏关联

排除法找出的真凶：**贵的股票恰好都 `luck` 为正，便宜的都 `luck` 为负**
（赤河酒业/启辰新能/瑞和银行 luck 为正且贵，恒泰置业/佳选食品/长风钢铁为负且便宜）。
于是"买最贵"间接买到了好运气 —— 优势来自 `luck`，不是来自价格。

用**分量消融实验**证实：把 `luck` 全部置零，优势立刻翻转为 **−3.47%**。

修法有两条，我先走错了第一条：

- ❌ **按价格重排 `luck`**（便宜给好运、贵给差运）→ 矫枉过正到 **−7.92%**，
  而且因为价格序已隐含趋势序，`corr(price, trend)` 仍是 **+0.41**，
  只是把问题从 luck 挪到了 trend。
- ✅ **反过来求解价格**（`luck` 不动）→ 用分档随机搜索重排定价，
  把 `corr(price, luck)` 从 0.26 压到 0.23（并手工微调），
  与语义锚点的平均偏差仅 ¥0.62 —— 定价仍然"像人定的"。

> `tools/diag-pool.mjs` 现在守着 21 条断言，其中包括：
> · 价格不得成为信号（**排列检验**，落点须在 20~80 百分位）
> · trend 与 luck **必须**能预测收益（> 2×SE）—— 反向断言，防止"把所有效应都洗掉"
> · 代码不得与真实 A 股号段碰撞
> · 价差比 ≥5、最低价 ≥3、无 floor 过高
>
> ⚠️ **改完价格请跑 `diag-pool.mjs`。不要去调相关系数，那是错的度量。**

#### ⚠️ 均值回归周期：本项目最容易做错的一步

最初 `trendBias` 是**恒定值**，导致高 trend 的股票每月稳定上涨，
"每月追最贵那只"的换手策略稳赚不赔（`balance` 测试抓出来了）。

**第一次尝试（失败）**：把恒定值换成 `sin((t/period)·2π + phase)`。
看起来"方向会翻转"，但受控实验一测 —— 个股 α 分量的自相关**居然是 +0.158（正！）**，
它非但没惩罚追高，反而在**奖励**追高。

原因：**价格是涨幅的积分，涨幅是价格的导数**。把 `sin` 直接当作**涨幅**，
则价格 ≈ −cos，涨幅曲线在半个周期内近似一条**平顶** —— 连续几个月都是同一个大正值。
于是"上月涨得多"几乎等价于"下月还涨得多"，妥妥的动量。

**正解**：让 `sin` 作用于**价格水平**，涨幅取其**一阶差分**（≈cos）：

```js
const dLevel = levelAt(t) - levelAt(t - 1);   // sin 差分 ≈ cos
const trendBias = prof.trend * K * 2.0 * dLevel;
```

cos 在**一个周期内会完整地由正转负**，峰值之后立刻衰减 ——
「上月最猛」恰好落在余弦下降段，次月涨幅显著低于均值。

叠加一个 2~3 个月的**副周期**后，回归点变密，追高更容易被套。

| 指标（受控实验） | 修复前 | 修复后 |
|---|---|---|
| 个股 α 分量自相关 | **+0.158**（奖励追高） | **−0.153**（惩罚追高） |
| 个股 α 分量 σ | 0.64 | 1.74（能与噪声抗衡） |
| "上月最强" 次月平均 | 高于全体 | 低于全体 |
| 最强档 − 最弱档 | +0.25% | **−0.23%** |

> 诊断工具链：`diag-momentum.mjs` 把 pathgen 的三个分量**分别**导出，
> 单独测各自的自相关，一眼定位动量来源。这类"整体指标正常但策略失衡"的
> 问题，只有拆开分量才能查——不要靠猜。

#### 退市爆雷（`rollDelist`）

- 只有 `luck` 明显为负的高危股才可能退市；熊市概率放大（见 `diag-delist`）
- 退市回合落在第 **3~10** 月，给玩家足够的"逃生窗口"
- 清算价跌到 **0.5~1.7 元** 的仙股价
- **一局最多一只退市** —— 保留 `luck` 最低的那只，避免三只全爆雷直接打死玩家

> 熊市年景配合"地产暴雷"的故事线：高杠杆地产股最容易命中退市。

#### ⚠️ 一条被写反的单调性断言

`diag-delist.mjs` 原本断言"小牛的退市率高于大牛"，实测**恰好相反**：
大牛 13.6% ＞ 小牛 8.8%。原因是 `bull` 虽然中枢更高，但 `marketVol`（3.4）
与 `crashChance`（3.5%）也都高于 `smallBull`（2.2 / 2%）——
**上行更猛的市场，波动也更大，踩雷概率反而略高**。

修法是改断言（`['bear','smallBear','flat','calmFlat','bull','smallBull']`），
不是改数据 —— 数据是对的，是我把"温和"错当成了"安全"。

### 2b. 年景层（`js/data/seasons/index.js`）—— v4 的核心

```js
season(
  'y01', 'bull', '全民入场',
  ['900101', '900201', '900501'],          // 3 只股票（行业必须互不相同）
  ['nl_01', 'nr_01', 'nt_01', 'nx_01', 'nl_06', 'nc_01'],  // 6 条专属新闻
  '营业部门口排起长队……',                    // 内部叙事（**不给玩家看**）
)
```

一个 `season()` **工厂函数**在**模块加载时**就做完整校验，任一条不满足**直接 throw**：

- 股票数必须 3、新闻数必须 6
- 3 只股票的 `sector` **必须互不相同**（否则"三只不重行业"的承诺就破了）
- 引用的每个 `code` / 新闻 `id` 必须真实存在于股票池 / 新闻池
- **每只股票至少有一条对口新闻**（本行业或 `macro`），否则该股在这个年景里"没有故事"

> **为什么用 throw 而不是 `validateData()`**：
> 数据错误应该**在写数据的那一刻**就炸，而不是等玩家点开始才在
> `validateData()` 里被列出来。这个设计立刻抓到了两处我手写的数据错误——
> `y04` 把材料写了两次（`materials/energy/materials`）、
> `y18` 把能源写了两次（`finance/energy/energy`）——**在 import 阶段就报错了**，
> 根本没机会变成运行时的静默异常。

20 个年景的风格分布（**刻意不均匀**，让某些风格更容易被抽到）：

| 风格 | 个数 | 年景标签 |
|---|---|---|
| `bull` | 4 | 全民入场 / 成长股领涨 / 白马抱团 / 周期反攻 |
| `smallBull` | 3 | 温和修复 / 结构行情 / 慢牛爬坡 |
| `bear` | 4 | 系统性下杀 / 债务出清 / 泡沫破裂 / 外围风暴 |
| `smallBear` | 3 | 阴跌磨底 / 反弹诱多 / 缩量下移 |
| `flat` | 3 | 箱体震荡 / 板块轮动 / 反复拉锯 |
| `calmFlat` | 3 | 横盘无量 / 消息真空 / 假日行情 |

**「不重复」是两个层次**：

1. **年景内不重复** —— 3 只股票必须来自 3 个不同行业（构造期强制）
2. **跨关不重复** —— 由 `DataBus.usedStockCodes` 累积排除

> ⚠️ **这一段已被连闯改写作废（见 §6b）。**
>
> 早先的默认路径是「一局 5 关用 5 个不同年景」，20 个年景 → 可连玩 4 轮（20 关）不重样。
> 但连闯要求"可以一直打下去"，而 **20 个年景 × 3 只 = 60 个股票位，池子只有 36 只，
> 必然重叠** —— 实测贪心选年景最多只能排出约 7 关互不重复
> （2000 次试验：6 关 17% / 7 关 51% / 8 关 32%），**年景层撑不起无限连闯**。
>
> 所以默认路径改成了 `composeFreshLevel()` —— 直接从 `STOCK_POOL` 抽股票，
> 用 `usedStockCodes` 做跨关排除，用"轮界补货"决定何时允许复用（连闯 10 关零重复）。
> 年景层保留下来只服务**受控实验**：显式传 `{ season }` 时仍走这条路径，
> `diag-rating` / `diag-styles` 靠它固定变量。

#### ⚠️ `pool: null` 曾被占位的 `style` 悄悄破坏

关卡用 `pool` 声明"本关可抽哪几种风格"：

| 关卡 | `pool` | 含义 |
|---|---|---|
| 第 1 关 | `['smallBull','bull']` | 先学会看盘 |
| 第 2 关 | `['smallBear','bear']` | 学会识别下跌 |
| 第 3 关 | `['flat','calmFlat']` | 没有趋势可依赖 |
| 第 4 关 | `['smallBull','smallBear','flat','calmFlat']` | 四种混合 |
| 第 5 关 | `null` | **全放开，什么都可能遇上** |

问题出在第 5 关：它还有一句 `style: 'flat'` 作为**兜底占位值**。
而 `composeGame` 早期的筛选顺序是**先 `style` 再 `styles`** ——
于是那句占位的 `'flat'` 把"全放开"硬生生压成了「只能抽 flat 年景」，
**400 次抽卡全部是 flat**，第 5 关的"没有剧本"完全失效。

还有更隐蔽的一层：`poolOfLevel()` 当时对全放开返回 `null`，
而 `null` 在调用方看来等于"没指定，那我用 `level.style` 吧" —— **兜底值反客为主**。

修法（两处，缺一不可）：

1. `poolOfLevel()` 对全放开返回**哨兵值 `'all'`**，而不是 `null` ——
   显式表达"这是全放开"，堵住调用方的"没指定"联想。
2. `composeGame` 的筛选优先级改为 **`styles`（池）> `style`（单值）**，
   并识别 `'all'` 表示不动候选。

> **通用教训**：`null` 与"未指定"在 JS 里长得一样，**用一个显式的哨兵值**
> 把"我明确要全放开"和"我没说"区分开。否则兜底默认值会静默覆盖掉设计意图，
> 而且**测试很难发现** —— 除非你恰好断言了"400 次应覆盖 6 种风格"。

### 3. 新闻池与"三类新闻"（`js/data/newspool.js`）

**77 条新闻**，**按板块分组**（LIQUOR…MEDIA + MACRO），每条带 `kind`：

| `kind` | 含义 | 结算时的漂移 |
|---|---|---|
| `relevant` | 板块命中持仓股 | `truth ? +drift : −drift` |
| `irrelevant` | 板块错配（船运 vs 陆运） | **0**（照常展示，但无影响） |
| `pressured` | 利好但业绩承压 | `−abs(drift) * 0.7`（照跌） |
| `macro` | 宏观，影响所有股票 | 按权重 ×0.5 生效 |

实际分布：`relevant` 65 条 / `pressured` 10 条 / `irrelevant` 2 条。

匹配规则是 **`news.sector === stock.sector`**（不再是旧的 `target` code 匹配），
这正是"同一批新闻能服务任意随机组合的三只股票"的关键。

**新闻卡的 UX 配合**：卡片上会显示「消息板块：X」和「你的持仓行业：…」，
以及一行 `※ 该消息涉及/未涉及你的持仓板块` 提示 ——
但**不会直接告诉你该买还是该卖**，判断留给你。

### 3b. 机构评级公式

```
score = 相对强弱 × 0.30 + 新闻 × 0.10 + 噪声 × 0.60
相对强弱 = (本股涨跌幅 − 本回合三只股票的均值涨跌幅) / 4   ，截断到 ±1
```

**走势因子必须减掉"大盘代理"（三只股票的均值）**。早期版本直接用本股绝对涨跌幅，
结果评级退化成了**大盘方向指示器**：实测大盘暴涨月里"看多档"下月上涨比例 97.8%、
"看空档"只有 0.8%；大盘暴跌月里"看多档"跌到 25.2%。
合并所有风格算 **IC = 0.307** —— 这不只是"太准"，而是**泄漏了本该隐藏的市场风格**
（关卡设计明令不告诉玩家年份与风格）。减掉均值后 IC 降到 **0.036**。

> ⚠️ 减均值有个必须知道的副作用：给三只股票减**同一个**常数**不改变它们的排序**。
> 所以评级的排序天然等于"本月涨幅排序"（实测排序一致率 70.9%）。
> 这是**刻意接受**的代价 —— 宁可让评级"只是在复述玩家已经看得到的行情"，
> 也不能让它当预言机。

评级是**板块感知**的，与股价结算用同一套三类新闻语义：

| 新闻 `kind` | 对评级新闻因子的贡献 |
|---|---|
| `relevant` + `truth` | 按 `truth` 取正/负 |
| `relevant` + `!truth`（假消息） | **取反** —— 不点破，只让方向背离 |
| `irrelevant`（板块不匹配） | **只贡献噪声**，方向随机 |
| `pressured` | **取正**（机构跟着标题看多，看不出利润是假的） |
| `macro` | 按权重 ×0.5 |

#### ★ 用户提的两个"评级太准"的例子，现在都成立

**例① 剧烈波动时，看多也会被大盘拖下去。** 大盘暴跌月（≤ −4%）里，
"看多档"下月**真的上涨**的比例只有 **12.5%**，而同期基准率（全体股票的上涨比例）是 12.2% ——
**超额仅 +0.3pp**，也就是评级在暴跌月里**一点信息都没有**，全被大盘拖走。
（旧版是 25.2%，且随大盘方向剧烈摆动。）

**例② 公司财务造假暴雷，评级看不穿。** `pressured` 语义已从"取负"改成"**取正**"：
旧版机构一眼识破，等于给玩家**免费预警**；现在机构跟着标题看多，随后业绩暴雷、股价崩塌。
实测暴雷前一个月给出"看空"的比例 **38.2%**，而全体样本里看空档占比 **35.9%** ——
只高 2.3pp，**没有预警能力**。（旧版是 53.9% vs 35.8%，高出 18pp。）

#### ★ 判"评级准不准"的正确判据

**不要用「跟评级 − 等权」当判据。** 市场本身有动量溢价：
"每月全仓本月涨最多的那只"这条**玩家自己就能跑**（行情面板上就写着本月涨跌）
的策略，月均比等权高 **+0.557%**；而"每月全仓评级最高的那只"是 **+0.514%** —— 几乎一样。
真正的判据是**评级的独占价值**：

| 指标 | 实测 | 含义 |
|---|---|---|
| 看多档下月上涨 | **50.3%** | 抛硬币 |
| 看空档下月下跌 | **51.2%** | 抛硬币 |
| IC | **0.036** | 几乎无预测力 |
| 跟评级 − 等权 | +0.514% / 月 | ← **不是**判据（这是动量溢价） |
| 跟动量 − 等权 | +0.557% / 月 | 玩家不用评级也能拿到 |
| **★ 跟评级 − 跟动量** | **−0.043% / 月** | **评级没有给玩家任何额外信息** |

**评级没有直接剧透真假**，而是通过轻微的方向分歧给出暗示。
因为噪声占六成，机构**经常看走眼** —— 这是玩法，不是缺陷。
用 `tools/diag-rating.mjs` 可随时复测这张表。

> **为什么不把噪声权重继续往上加**：实测加到 0.68 / 0.79 会让"看多档下月上涨比例"
> 掉到 50% 以下（49.4% / 48.9%），也就是评级从"不准"变成"**反着准**" ——
> 玩家会发现反着做更赚，那是另一种更糟的作弊。0.60 是"抛硬币且不倒挂"的水平。

> **新闻权重为什么是 0.10**：接通 `applyNews` 之后新闻会真的推动价格（且持续 2 个月），
> 而评级会读新闻 —— 于是评级重新变得"能预测"（新闻权重 0.14 时 IC 0.047、极差 2.78%）。
> 所以必须压住；但**又不能压到 0**，否则评级与新闻永远不会背离，
> "从评级与新闻的背离里嗅出假消息"这个核心爽点就没了。0.10 是实测的平衡点：
> 强消息能推动 ±0.10，刚好够把边界上的评级推过一档（档宽 0.15~0.35），又不足以让玩家照抄。

### 3c. 排查"价格波动 / 机构评级 / 消息"时挖出的两个静默缺陷

这一轮排查的起因是"评级太准"，但顺着价格与消息链路查下去，
挖出两个**不报错、不崩溃、只是默默算错**的缺陷。它们都没有任何日志，
只能靠"自己写一个探针把中间量打出来"才能发现。

#### 缺陷① 新闻对价格**零影响**（整条消息链路是死的）

`simulator.applyNews(news)` 这个函数**定义好了，但从来没有被调用过**。
`DataBus.nextTurn()` 只做了 `this.news = this.dispatcher.newsOf(turn)`，
忘了把它注入行情引擎。后果：

- `simulator.effects` 永远是空数组 → `_activeDrift()` 恒返回 0 → `newsChange` 恒为 `0.000`
- 为"暴雷"设计的 `pressured`（利好但业绩承压）机制**从未生效**
- 本作的核心爽点"老手从评级与新闻的背离里嗅出假消息"**根本没有可背离的对象** ——
  新闻不动价格，评级背离了也没有意义
- 玩家认真读新闻做判断，而新闻其实什么都没影响

**修法**：在 `nextTurn()` 里补上 `this.simulator.applyNews(this.news)`。

**怎么发现的**：写了个探针直接打印 `simulator.effects.length` 与 `newsChange`，
看到恒为 `0` / `0.000` 才确认。修完复测 `news=-3.200`。

> 这个缺陷的教训：**"函数存在"不等于"函数被调用"**。
> 所有静态检查、类型检查、单元测试（如果只测 `applyNews` 本身）都抓不到它。

#### 缺陷② 退市当月**上报的涨跌幅与实际价格矛盾**

`simulator.step()` 上报的 `change` 用的是**计划涨跌幅**（`totalChange`），
而不是价格真正走出来的涨跌幅。退市爆雷时两者天差地别：

```
价格  ¥8.50  →  ¥1.20     实际跌幅 −85.9%
上报  totalChange = −0.8%  ← 把"腰斩"显示成"小跌"
```

原因是退市分支直接 `next = def.delistPrice`（或 `def.floor`）硬赋一个仙股价，
压根没走 `totalChange` 那条路；触底（`next` 被 `def.floor` 兜住）时也有同样的偏差。

**修法**：改用价格转移算出来的**实际**涨跌幅：

```js
const actualChange = prevPrice > 0 ? (st.price / prevPrice - 1) * 100 : 0;
```

并在 `diag-delist.mjs` 里加了一条自洽性断言（抽查 60 次退市事件，
断言 `|上报 change − 价格反推 change| ≤ 0.15%`）。
旧版平均少报幅度 **76.3 个百分点**，修完后不符 **0 例**。

### 4. 交易规则（A 股真实规则）

| 项目 | 规则 |
|---|---|
| 一手 | 100 股 |
| 买入 | 必须整手（100 的整数倍） |
| 卖出 | 可以零股 |
| 买入成本 | 佣金 **万三**，最低 ¥5 |
| 卖出成本 | 佣金 万三（最低 ¥5） **+ 印花税 千一** |

> **为什么卖出要多收千一印花税**：起初两边都是万三，结果每次全换手成本只有
> ¥6+¥6=¥12（约 0.12%），一年的换手磨损才 1.4% —— 惩罚形同虚设。
> 加入千一印花税后，单次全换手约 0.16%（一年约 2%），
> 才让"频繁交易是有代价的"这一课真正成立。这也是真实 A 股的规则。

### 5. 破产判定

```
totalAssets = cash + Σ(持仓股数 × 当前价)
totalAssets < min(所有股票价格) × 100     →  破产
```

判定口径是**总资产**（现金 + 持仓市值），**不是现金**。当前破产线约 **¥900**。

> ⚠️ **这里踩过一次坑**：早期版本只看 `cash < 最低一手成本`，结果玩家只要一买股票
> （哪怕只买一手）现金就跌破线，回合末立刻被判破产 —— 等于**惩罚正常买入**。
> 实测数据显示「定投不卖」破产率 100%、「反向买差评」破产率 99%，全是误伤。
> 持仓是能卖成钱的，必须计入总资产。

**判定时机**（三条）：

| 时机 | 说明 |
|---|---|
| 卖出后 | 卖出回笼现金，但若已无翻盘手段则在此出局 |
| 非末回合的回合末 | 价格结算 + 评级之后判定 |
| ~~买入后~~ | **不判** —— 买入只是把钱换成股票，总资产几乎不变，该给玩家整月调整 |

买入时若会把总资产压到破产线以下，交易面板显示 `⚠ 买后总资产 ¥x < 破产线 ¥y`
作**软提示**（不硬拦，玩家有权利梭哈，但应该被告知后果）。

### 6. 无通关目标 + 年末强制平仓

关卡不设硬性收益目标，`goal.type = "term"`。交易满 12 个月即到期。

**到期结算两步走**：

```
① 强制平仓 —— 所有持仓按当前市价卖出（含手续费）
② 用平仓后的纯现金判定 win / lose
```

为什么要强制平仓：持仓是"账面富贵"，不卖出只是数字。年末清仓后最终资产变成
实打实的现金，结算数字才真实，也杜绝**"死扛不卖躺过终点"**。

平仓结果会写进 `bus.result.liquidation`，结算界面额外显示「年末平仓」和「平仓盈亏」两行；
空仓到期则不产生明细。

这样设计的原因：固定路径市场的收益上界是**有限且可计算**的（当前约 ¥15,000），
硬性目标很容易定成"数学上不可能达成"。去掉目标后，比较对象变成**自己的本金**，
难度天然合理，也鼓励玩家反复挑战更高收益。

### 6b. 连闯（多关接力）

玩家的诉求：「每关结束可以选择自动进入下一关还是返回主界面，进入下一关延续上一关
结束时的资金状态。五关结束后可以选择继续，将再来五关。也可以选择退市结算。注意，
每关不要重复相同的股票，股票数量要是 3 的倍数，避免最后一关只剩 1-2 只股票的情况」

一句话概括：**关卡不再是孤立的一局，而是一条可以一直走下去的路。**

#### 三个出口

结算页的按钮集合由 `result.js` 的 `actionsOf()` 决定，三档互斥：

| 状态 | 按钮 | 说明 |
|---|---|---|
| 普通关 | `进入下一关`（主） / `返回主界面`（次） | 默认路径 |
| 轮末（第 5 / 10 / 15 … 关） | `继续 · 再来五关`（主） / `退市结算`（次） | 一轮 = 5 关 |
| 破产 | `返回主界面` | 连一手都买不起了，没有"下一关"可言 |

> ⚠️ **破产分支必须最先判断**。否则破产时还会摆出"进入下一关"，
> 点进去就是拿 ¥0 开局 —— 玩家会直接认为游戏坏了。

#### 资金延续：`result.total` → 下一关的 `initCash`

上一关结束时 `settleTerm()` 已经**强制平仓**，所以期末状态是纯现金。
`startNextLevel()` 直接把 `result.total` 作为下一关的起始资金，不需要搬运持仓：

```js
const info = this.nextLevelInfo();
const cash = this.result.total;   // 上一关期末总资产
this.start(info.id, { initCash: cash });
```

> ⚠️ **`LEVELS` 是共享对象数组，绝不能把连闯资金写回 `level.initCash`。**
> 曾经有版本这么写，结果第 1 关的本金被永久污染 —— 重开一轮时起始资金变成了
> 上一轮的期末资产。现在资金一律走 `DataBus.initCash`，
> 结算页显示的是 `bus.initCash` 而不是 `bus.level.initCash`。
> `diag-levels` 有一条断言专门守着这件事（`level.initCash === 10000`）。

#### 股票不重复：为什么是"轮界补货"

`usedStockCodes` 记录本局已出现过的股票，下一关抽卡时排除。难点在于
**什么时候允许重新出现用过的股票**，三种做法都试过：

| 做法 | 结果 |
|---|---|
| ✗ 每轮清空 | 只保证"一轮五关不重样"，**第 6 关立刻撞上第 1 关**。太保守，36 只的池子一轮只用掉 15 只 |
| ✗ 用完才清（剩 < 3 只） | 能连闯 12 关不重样，但**清空点落在第 13 关**，而轮界在 11 关 —— 第 3 轮内部会撞车 |
| ✓ **轮界补货**（本实现） | 在轮界检查"剩下的没用过的股票够不够撑满一整轮"，不够才清空 |

`startNextLevel()` 里的核心三行：

```js
if (info.newRound) {
  const remain = STOCK_POOL.length - this.usedStockCodes.length;
  if (remain < 3 * LEVEL_COUNT) this.usedStockCodes = [];   // 3 × 5 = 15
}
```

36 只的实测结果：

| 轮次 | 关卡 | 用掉 | 剩余 | 轮界是否清空 |
|---|---|---|---|---|
| 第 1 轮 | 1–5 | 15 | 21 | 否（21 ≥ 15） |
| 第 2 轮 | 6–10 | 15 | 6 | **是**（6 < 15） |
| 第 3 轮 | 11–15 | 15 | 21 | 否 |

→ **连闯 10 关都不会看到重复股票**，且每一轮内部绝对不重样。

#### 为什么股票池必须是 3 的倍数

一轮 5 关 × 每关 3 只 = 15 只。清空点必须落在**关卡边界**上，否则会出现
"最后一关只剩 1-2 只股票"的残缺局面。`STOCK_POOL.length % 3 === 0`
是这条不变量最便宜的守护方式，`diag-pool` 与 `diag-levels` 各有一条断言守着它。

为此股票池从 34 只扩到 **36 只**（12 个行业 × 3 只），刚好让每个行业都凑齐 3 只。

#### 版面：两个按钮必须**并排**，不能堆叠

```js
// _flow()：按钮区**先分配**，再让上面的内容去挤
const btnY = bottom - bh - 14;             // bh = 52
const bw = actions.length > 1 ? Math.floor((pw - gap) / 2) : Math.min(220, w - 90);
```

堆叠时按钮区要占 `2×52 + 12 = 116px`，正好把轮末多出来的两行
（本轮累计 / 累计收益率）的差额吃光 —— **轮末的走势图会整块消失**，
而玩家恰恰是在轮末最需要看走势来决定"继续还是收手"。并排只占一行 52px，
代价是每个按钮窄一半，所以文案也相应缩短（`继续 · 再来五关` 而不是
`继续，再来五关`），字号从 `md` 降一档到 `sm`。

走势图有三级降级链，且**整块**（标题 + 图例 + 折线）一起开关：

```js
const room = btnY - 14 - chartY;
const chartH = room >= 96 ? 96 : room >= 52 ? room : 0;
const showChart = chartH > 0 && seriesCount > 0;
```

> ⚠️ 曾经只把折线交给降级链，标题和图例照画 —— 屏幕上就剩一堆没有图的
> "开 / 2月 / 4月…"刻度，比不画更糟。

实测（`diag-layout` 断言覆盖）：

| 机型 | 普通关 | 轮末 | 小屏 320×568 |
|---|---|---|---|
| iPhone 15 Pro 393×852 | 图 96px | 图 96px | — |
| Android 412×915 | 图 96px | 图 96px | — |
| 小屏 320×568 | 图 0（整块不画） | 图 0（整块不画） | 空间不足，优雅降级 |

#### 退市结算：把整轮战绩汇总成一份结算单

`finalSettle()` 的口径：

| 字段 | 取值 |
|---|---|
| `init` | 第 1 关的起始资金（整轮本金） |
| `total` | 末关期末总资产（已强制平仓，纯现金） |
| `turns` | **各关存活月份之和**（"累计月份"，不是单关的 12） |
| `levels` | 连闯关数 |
| `isFinal` | `true` —— 结算页据此切换文案 |

> ⚠️ 必须把 `runMode` 关掉。否则 `actionsOf()` 看到 `runMode && canContinue`
> 仍会摆出"进入下一关"，玩家点一下就真的继续了 —— 退市结算必须是一锤子买卖。
> 配套地，`canContinue()` 与 `startNextLevel()` 都加了 `result.isFinal` 守卫，
> 双保险。

结算页的行也随状态切换：`存活月份 12 / 12`（单关）→ `累计月份 36 个月`（退市结算），
标题从「这 一 年 赚 了」换成「退 市 · 满 载 而 归」。

```
菜单 startGame  → startRun(levelId)      资金 = 该关默认初始资金
                        ↓

        ┌───────────────┼───────────────┐
        ↓               ↓               ↓
  nextLevel        final            menu

```

### 7. 回合流程

```
每个月都是同一套流程（含 12 月）：

① 新闻插播  →  ② 玩家决策（买卖）  →  ③ 点"下月 / 结束本年"  →  ④ 行情结算 + 机构评级
   →  ⑤ 若是最后一月 → 到期判定（强制平仓 + 收益结算，结束）
      否则 → 进入下一月
```

> ⚠️ **回归过的坑：每个月都必须真正进入交易界面**（含 12 月）。
>
> 曾经的写法是新闻关闭后直接调用 `_settleAndJudge()`，而这个函数里含
> `isTermOver()` 判定 —— 于是 12 月的新闻一关掉就立刻跳结算，玩家**根本没机会做
> 12 月的交易**。玩家反馈的「十二月就没有新闻了，关卡已经结束了」正是这个现象
> （新闻其实播了，但交易界面被瞬间跳过）。
>
> 修法：把「进入交易」与「结束一期」拆成两个互不重叠的方法：
>
> | 时机 | 方法 | 做什么 |
> |---|---|---|
> | 关掉新闻 | `_enterTrading()` | 只做价格结算 + 生成评级，**不做任何判定** |
> | 点下月/结束本年 | `_advanceTurn()` | 非末月 → 下一回合；末月 → `_endTerm()` |
> | 末月收尾 | `_endTerm()` | 强制平仓（按市价卖出）→ 用纯现金判 win / lose |
> | 卖出后 | `checkBankrupt()` | 总资产口径破产判定 |
>
> 还有两处配套的 UX 提示，让末月"看得出来是末月"：
> - 顶栏显示 `十二月` 且副标题写「最后一个月 · 月末平仓」（红色强调）
> - 底部按钮改为「结束本年 ▶ 结算」，不再是「进入下一个月 ▶」
> - 新闻卡的报头也带月份名（`十二月`），避免玩家不知道自己打到哪了
>
> `tools/selftest.mjs [11]` 会锁死这个不变量：12 个回合**逐一**断言「可交易」。

顺序说明：**到期优先于破产**。末日总资产不足一手时，平仓把持仓换成现金后仍是同一笔钱，
交给到期结算按收益判定，比简单判破产更准确（玩家可能是亏了但没亏光）。

### 8. 走势图（自写 Canvas 折线图）

玩家的诉求：「股票走势能不能换成坐标图可以查看的，图里是直线带箭头的」＋
「把图表做成按钮点击弹窗查看」＋「走势图按钮替换掉之前写的 canvas，
按钮点击只看这个按钮在哪只股票下面」＋「走势图太直了，加入一些波动」＋
「当月三只股票的走势完全一样」（要每股不同）。

由于小程序图表库在小游戏里全部不可用（见「平台约束 3」），图表是**自己画的**：
`js/styles/chart.js`，零依赖，导出四个函数。

| 函数 | 作用 |
|---|---|
| `arrowLine(ctx,x1,y1,x2,y2,color,lw,head)` | 带箭头线段（实心三角沿线段方向） |
| `lineChart(ctx, opts)` | 完整坐标轴 + 网格 + 刻度 + 多序列折线 + 末端箭头 + 生长动画 |
| `chartLegend(ctx,x,y,w,entries)` | 色块 + 名称 + 涨跌幅（**涨红跌绿**） |
| `wavyPath(closes, code, opts)` | 把月度收盘价展开成带**固定波动**的高密度采样序列 |

`lineChart` 会自动算数据范围并留 8% 余量、为纵轴标签预留 40px、横轴标签 14px；
`animate` 传 0~1 可做逐月生长动画。**全平线**会人为撑开范围避免除零。
参数 `positions` + `labelAt` 支持**非均匀横轴** —— 月度点之间插了月内波动点后，
月份标签仍能对齐到正确位置。

#### 月内波动（`wavyPath`）

只有 12 个月度点时，折线就是 12 条直段的折线，"太直"。做法是在相邻两个月度
收盘价之间插入 5 个采样点，让曲线呈现真实股票的锯齿感。

四条不可动摇的契约（`tools/diag-wavy.mjs` 用 24 项断言守住）：

1. **端点精确等于收盘价**。月度收盘价就是结算价，若走势图与之不符，
   玩家会看到"图上是一个价、扣款是另一个价"。
   实现用**桥形权重** `sin(π·t)`：两端为 0、中间最大，所以偏移在端点严格归零。
2. **每股形状不同**。早期版本波形只跟 t 有关，导致**三只股票走势完全一样**
   （只是被各自收盘价缩放）。现改为由**股票代码派生的固定相位**：
   `phasesFor(code)` 对代码做 FNV-1a 哈希，取三个字节段映射成 3 个相位偏移。
3. **完全确定性、零随机**。哈希是**纯函数**，所以
   `wavyPath(同一 closes, 同一 code)` 永远同一结果，
   `wavyPath(不同 code)` 得到不同形状 —— 「每股不同」与
   「反复打开图不会变」**并不矛盾**，可以同时满足。
   > 玩家明确要求「确保这个按钮每次点击打开的图不会变」。
   > 注意：**不要用 `Math.random()` 或"运行期种子"** —— 那会破坏可复现性，
   > 也会污染全局随机序列、影响已有测试基线。
4. **波动幅度受控**。振幅 = `max(a,b) × (1.2% + 涨跌幅×0.18)`，
   叠加后按经验峰值系数 `1.20` 归一化再夹紧到 `[−1,1]`，避免出现夸张深谷。

`[5]` 段用**记录型 ctx + 真实 TradingScene** 反复开关弹窗 4 次，
逐条比对绘制指令，要求**逐字节一致**。

#### 弹窗页头布局

`关闭` 按钮放在**左上角**，股价 + 涨跌放在**右上角**，分居两侧。
> 早期版本两者都在右上角（关闭按钮 `r.y+10~+32`，股价 `r.y+30`），发生重叠。
> `diag-wavy` 的 `[6]` 段用几何断言守住：`关闭右边界 < 股价文本左边界`。

**两处接入**：

1. **交易场景** — **每张股票卡片右下角**各有一个 `走势图 ▤` 按钮（`_chartBtns[code]`）。
   点开弹出全屏覆盖层，**只画该按钮所属那一只股票**的走势：
   单序列折线 + 图例 + 最高/最低统计，颜色跟随该股区间涨跌（涨红跌绿）。
   关闭方式：左上角 `✕ 关闭`，或点弹窗任意处。
   > 这里**不再内嵌迷你 canvas**。早期版本曾在卡片里画一条 80×26 的小折线，
   > 现已被按钮取代 —— 原因是小折线信息量过低且与真实走势图重复。
   > 关键是"一只股票一个按钮"（热区注册在卡片之后，后注册优先命中，
   > 所以点按钮不会误触卡片选中）。
2. **结算场景** — 用一张合并的多序列折线图替代原来每只股票一个柱状图，
   同样接入 `wavyPath`。

`tools/diag-chart.mjs` 用**记录型假 ctx** 从绘制指令层面反推几何正确性
（坐标轴方向、越界、NaN、动画越界、涨跌配色），共 38 项断言 —— 这些错误渲染时
不抛异常，普通"渲染无异常"断言抓不到。

### 9. 难度平衡（实测数据）

八种策略各跑 **600 局**（牛市 lv_01，固定种子 `balance-v1`）：

| 策略 | 盈利率 | 破产率 | 平均资产 | 平均磨损 |
|---|---|---|---|---|
| 躺平不动 | 0% | 0% | ¥10,000 | ¥0（0 笔） |
| 定投不卖 | 82.8% | 0% | ¥10,988 | ¥72（12 笔） |
| 定投止盈 | 86.3% | 0% | ¥10,539 | ¥83（14 笔） |
| 跟机构买 | 79.8% | 0% | ¥10,921 | ¥73（11 笔） |
| 反向买差评 | 85.2% | 0% | ¥10,681 | ¥33（5 笔） |
| 首月梭哈 | 86.3% | 0% | ¥11,993 | ¥22（2 笔） |
| **满仓持有**（基准） | 84.8% | 0% | **¥12,099** | ¥22（2 笔） |
| **换手梭哈** | 86.8% | 0% | ¥12,049 | **¥237（24 笔）** |

**设计意图**：

- **躺平不动必输**（0%）—— 不参与就没有收益
- **满仓持有是基准**（¥12,099）：一次性买入、从不换手
- **高频换手要付 10 倍以上的交易成本**（¥237 vs ¥22，占本金 2.37%）
- **跟机构买最容易被打脸**（79.8%，全场最低盈利率）—— 假消息确实在起作用
- **策略有区分度**：盈利率 0% ~ 86.8%，资产 ¥10,000 ~ ¥12,099

`tools/balance.mjs` 守住 14 条基线，其中关键的三条：

1. ★ **任何策略都不应因买入而被判破产**（总资产口径的回归断言）
2. ★ **正常持仓策略应当能活满 12 个月**
3. ★ **高频换手的交易成本必须显著高于买入持有**（≥5 倍）

#### ⚠️ 一条被推翻的断言：为什么不再说"换手一定亏更多"

最初这条断言是 `换手资产 < 满仓持有资产`。它**被推翻过两次**：

**第一次（样本太小）**：跑 6 次失败 3 次 —— 两个高方差均值做硬比较，200 局就是抛硬币。

**第二次（前提根本不成立）**：样本提到 600 局、加上印花税后，跨 5 个固定种子测，
换手仍在 **2/5** 的种子里反超。根因是**设计本身**：

> 为防"买最贵那只必胜"，pathgen 刻意让 `basePrice` 与 `trend` **完全不相关**（r≈0.04）。
> 既然价格高低不携带任何未来收益信息，"买最贵的"和"买最便宜的"就是**同期望**的随机选择。
> 换手唯一的真实代价是手续费（~2%/年），而它**落在年度收益 ±20% 的噪声里**，注定测不出显著差异。

**结论**：断言从"收益更低"（统计上不成立）改成"**成本更高**"（确定性成立、随换手线性增长）。
这才是这条机制的正确刻画 —— 换手策略**仍有教学价值**（摩擦成本样本），
但不能用"资产高低"去量化它。

> **通用教训**：断言要选**确定性成立**的性质，而不是"看起来该成立"的统计关系。
> 当一个断言时绿时红，先问"这是噪声，还是现象本身不存在"—— 后者更常见。

#### 测试自身的 bug（同时修掉）

`buyAndHold` 用闭包 `done` 标记"只买一次"，但这个闭包是**模块级、只创建一次**的 ——
200 局里只有第 1 局真的买入，其余 199 局输出 `¥10000 / 0%`。
修法是给策略加 `reset()`，在每局开头调用。
> **通用规则**：凡是"跑 N 局"的测试用到带状态的策略，都必须能复位。

> ⚠️ **已知设计缺口**：手续费磨损（万三 + 千一）仍不足以击穿 ¥10,000 本金，
> **破产结局在牛市中不可达**。真正的失败压力来自**熊市关卡的退市爆雷**
> （见 `diag-delist.mjs`：大熊年景退市率 95.5%，持仓被强制清算到仙股价）。

### 10. 字号与安全区（灵动岛不再遮挡）

玩家反馈：「字体可以稍微调大点吗？布局有点紧凑，苹果灵动岛有遮挡，可以在上方留出点空隙吗？」
三个症状，三处根治，外加一个"以后不会再犯"的结构性约束。

#### 10.1 字号整体放大 ~20%

`js/styles/palette.js` 的 `FONT.size` 从 `10/12/14/18/24/32` 提到 **`12/14/16/20/28/38`**。
配套加了一个 `shadowOffset(size)`：`size >= 18 ? 2 : 1` —— 字大了描边偏移也得跟着大，
否则大字号看起来会发虚。

#### 10.2 安全区只有一个真相来源：`js/styles/layout.js`

```js
safeTop()      = max(state.top, MIN_TOP=24)   // 下限**焊死在函数里**
contentTop()   = safeTop() + TOP_GAP(8)
safeBottom()   = max(state.bottom, MIN_BOTTOM=10)
contentBottom(h) = h - safeBottom()
```

两个关键取舍：

1. **下限焊在 `safeTop()` 里，而不是让调用方判断。**
   这样即使某个场景忘了接安全区，它拿到的也是 `24` 而不是 `0` —— 安全是**默认行为**，
   不依赖每个场景的作者记得这件事。
2. **背景仍然从 `y=0` 开始铺，只有内容从 `contentTop()` 开始。**
   如果连背景都下移，屏幕顶部会露出一条白边，比被灵动岛压住更难看。

`Renderer._setup()` 调一次 `setSafeArea(info)`；取不到 `safeArea` 时回退 `statusBarHeight`，
底部由 `screenHeight - safeArea.bottom` 反推。

#### 10.3 竖向节奏改成自适应，而不是写死

交易场景的高度分配不再是固定值，而是一个**求解器**（`solveHeights`）：
富余时先撑大间距、再长卡片；不够时依次压间距 → 压操作面板 → 压卡片，
每一层都有硬下限。退市横幅还要降级（两行 → 一行 → 悬浮盖在评级面板上），
但**绝不覆盖股票卡片**。

#### 10.4 结构性约束：一个场景只允许有一个"流"

`layout()` 和 `render()` 必须从**同一个** helper 取几何
（`tradeFlow()` / `menuFlow()` / `_cardLayout()` / `_flow()`），
不许出现两套平行的竖向累加器。这类"布局算一次、绘制算另一次"的漂移，
是这套代码里最容易产生、最难定位的 bug。

#### 10.5 只有"看"才能发现的 bug

`tools/diag-layout.mjs` 的 224 条断言全绿之后，`tools/shot.mjs` 把绘制指令重放到真 canvas
截图出来一看 —— **走势图的线飞出了面板外**。

根因：调用方用收盘价 `closes` 算纵轴范围，但画出来的其实是带月内波动的 `wavy` 路径，
平年时 `wavy` 会超出 `closes` 的极值。**断言测的是"不越界"，而这条线恰恰在越界**——
因为断言检查的是别的矩形。

两边都修了：调用方改用 `wavy` 的极值定轴（"最高/最低"仍报真实收盘价），
`chart.js` 的 `toY()` 加了兜底 clamp。

> **通用教训**：几何断言能证明"没撞上已知的框"，证明不了"画面对不对"。
> 改动版面之后，除了跑断言，还要**真的看一眼**。
> 这就是 `tools/shot.mjs` + `preview/layout-preview.html` 存在的理由。

#### 10.6 反向自检

`diag-layout.mjs` 里有一台**故意造出来的极端机型**：`safeTop = 100`、393×852。
如果实现里根本没读 `safeArea`，文案就会停在固定 y 上撞破断言。
这台机器存在的意义是证明**这套断言真的有牙齿**，而不是恒真。

### 11. 音频（背景音乐 + 音效）

需求：「这首曲子能放在游戏里播放吗」→「纯粹的背景音乐，循环播放就行」，
后来追加「下载个合适的按钮点击音效，并且在左上角加个关闭声音的按钮」。

#### 11.1 原始素材不能直接进包

拿到的 `sonilo_music_*.m4a` 有 2.15 MB，解析后发现两个问题：

| 项目 | 实测 | 问题 |
|---|---|---|
| 容器 | **fragmented MP4**（2441 个 `moof`，`mvex` 存在） | `mvhd.duration = 0`，时长元数据是空的 |
| 码率 | 301 kbps AAC-LC 立体声 44.1kHz | 对 BGM 严重过剩 |
| 时长 | 60.02s | — |

`m4a` 在 iOS / Android 上都能播，但**分片 MP4 + 时长为 0** 是个真实的兼容风险：
部分播放器会拒绝、或把时长算成 0 导致进度条与循环异常。
所以先转码成普通 MP3 —— 顺带把体积压掉 68%。

#### 11.2 转码：没有 ffmpeg 也能做

系统里没有任何 `ffmpeg`，改用 **PyAV**（自带 ffmpeg 库，纯 wheel 安装）。
`tools/transcode_bgm.py` 干三件事：解成 PCM（顺带把分片结构摊平）→
掐掉首尾静音（循环时首尾留白会听出"空一拍"）→ 按目标码率重编码。

结果：**2205 KB → 704 KB（31.9%）**，60.003s，96 kbps 立体声，带 Xing 头。

> **★ 踩到的坑**：PyAV 的 `AudioFrame` plane 缓冲区**带对齐填充** ——
> 1024 个采样（真实 2048 字节）返回 `buffer_size = 2112`。
> 直接 `bytes(plane)` 会每帧多吃 32 个采样：2585 帧累计多出约 8.2 万个样本，
> 既把时长拉长了 1.83 秒，**又把填充字节当成音频样本写进了输出**（每 23ms 插一段杂音）。
> 正确做法是按 `samples × 每采样字节数` 截断。
>
> 这个 bug 从"测试全绿"里完全看不出来 —— 是逐秒 RMS 曲线对比才发现的。

#### 11.3 播放模块 `js/core/bgm.js`

- 全程只用一个 `InnerAudioContext`，`loop = true`，不切歌、不排队
- **静音 = 把 `volume` 压到 0，不停播** —— 取消静音立刻接上，没有断点
- 静音状态写进 `wx.setStorageSync`，下次进游戏沿用
- `src` 可外部注入：`init({ src: 'https://…/bgm.mp3' })` 就能把这 704 KB 从代码包里摘出去
- 所有 `wx` API 都先做存在性检查 —— 无头测试环境没有这些 API，绝不能抛异常
- `obeyMuteSwitch: false`（手机静音也照放）：游戏类小程序的常见做法，
  否则用户一开静音就以为游戏没声音。想跟随系统静音改 `OBEY_MUTE_SWITCH` 即可
- `ensurePlaying()` 兜底：iOS 上首次用户交互前音频可能被系统拦下，
  主循环在第一次触摸时推一次（已在播时是空操作）

#### 11.4 打包范围（顺手补上的一个真问题）

`project.config.json` 的 `packOptions.ignore` 原本是**空的** —— 整个仓库 7.62 MB
会被原样打进包，**超过 4 MB 主包上限**。

补上忽略清单（测试 / 文档 / 备份 / `.git` / 原始 m4a 素材）之后：

| | 体积 |
|---|---|
| 代码（`js` + 三个入口文件） | 301 KB |
| 音频（`audio/bgm.mp3` 704 KB + `audio/click.wav` 4.6 KB） | 709 KB |
| **实际进包合计** | **959.3 KB** |
| 主包上限 | 4 MB |

`diag-audio.mjs` 的第 [5] 节守着这份清单，还会反过来断言"不忽略时确实会超限"，
防止将来有人以为忽略清单是多余的而删掉它。

#### 11.5 点击音效：怎么算"合适"

「下载个合适的点击音效」——"合适"得能验证，所以先定标准再挑：

| 指标 | 为什么 | 目标 |
|---|---|---|
| 有效时长 | 超过 120ms 会拖慢操作节奏 | 30~120ms |
| **起始延迟** | 前面留静音 = 点击"慢半拍"，最伤手感 | < 2ms |
| 峰值电平 | 太轻听不见、太满会爆 | −6 ~ −3 dBFS |
| 干净衰减 | 带混响尾巴会跟下一声叠在一起 | 单调衰减 |

拉来 40 个候选（36 个 Mixkit MP3 + 4 个 OpenGameArt CC0 WAV）逐个量化打分。
Mixkit 那批**全部不合格**：时长都在 1.1s 左右，尾部还有约 0.85s 的静音，
而且编码延迟不可控。最终选了 CC0 的 `qubodup-click2.wav`（55ms、零起始静音、峰值 −7.1dB）。

`tools/make_sfx.py` 负责加工：解成单声道 → 掐静音 → 归一到 −3 dBFS →
加 1.5ms 淡入淡出（防爆音）→ **同时输出 WAV 和 MP3 并复测两者的起始延迟**。

**素材来源与授权**（40 个候选的临时目录已清理，需要重新调音时按此重下）：

| 项 | 内容 |
|---|---|
| 最终采用 | `qubodup-click2.wav`，来自 OpenGameArt「Click / Hover sounds」包 |
| 作者 | qubodup |
| 授权 | **CC0 1.0**（公共领域，可商用、可修改、无需署名） |
| 备选来源 | Mixkit（free sound effects，同样可商用）—— 实测全部不合格 |

成品 `audio/click.wav` 是上述素材的衍生文件（降混单声道 + 归一 + 淡入淡出），
CC0 不要求署名，此处记录只为可追溯。

#### 11.6 为什么音效用 WAV 而不是 MP3

这是个反直觉的结论，所以两种都实测了：

| | 起始延迟 | 体积 |
|---|---|---|
| MP3（LAME） | 0.00ms | 1,088 B |
| WAV | 0.39ms | 4,728 B |

MP3 反而更"准"，因为 LAME 会写 Xing 头让解码器把编码器延迟剥掉。
但**官方文档写着「目前两个平台完全支持的音频格式有 mp3、aac、wav」**，
WAV 是唯一不用赌解码器行为的选项；4.6 KB 的体积差在 4 MB 预算面前不值一提。
**结论：50ms 级的短音效选 WAV，把"确定性"买回来。**

> 官方另一条被忽略的规则：**「对于相同的音效，应该复用已有的音频实例」**。
> 所以 `playClick()` 用 3 个实例的池轮转，而不是每次 `createInnerAudioContext()`；
> 复用前必须先 `stop()` 归零，否则连点会叠在一起。

#### 11.7 全局静音开关 `js/ui/mute-button.js`

按钮放在**顶部安全区这条带子的左下角** —— 和灵动岛同一水平线，
利用的正是灵动岛左右两侧的留白。硬约束：`y + h ≤ contentTop()`，
所以它**永远不侵占任何场景的内容区**；安全区太矮（无刘海机型只有 20px）时按钮自动缩小。

静音的归属从 `bgm.js` 挪到了 `js/core/audio.js`：一个开关同时管 BGM 和音效。
`bgm.js` 的公开 API 一字未改（内部改为订阅 `audio.onMuteChange()`），
所以原有的 67 项断言全部原样通过。

点按钮两个方向都给一声反馈：关掉时先响再静音，打开时先静音再响
（静音状态下调 `playClick()` 是空操作，听不见）。少了任何一边，
用户都会怀疑"按钮到底生效了没有"。

> **★ 全局覆盖层必须"惰性"**：它只许用 `fillRect` / `strokeRect`，
> **绝不能发路径操作**（`moveTo` / `lineTo`）。
> 画布路径是全局状态，覆盖层一旦往路径里塞点，就会被场景级的
> "折线是否越界"断言误当成自己的路径点。
> 所以底板特意没用 `widgets.panel()`（它的立体亮边是 `moveTo/lineTo` 画的），
> 改成两条细矩形，视觉等价、零路径点 —— 并且把这条写成了断言。

#### 11.8 ★ 踩到的坑：`snap()` 逐格对齐把点阵画裂了

**这个 bug 是"看"出来的，不是测出来的** —— 12 倍放大截图后发现图标上有 3 条 1px 黑缝。

原因：`snap(v) = Math.round(v / 2) * 2` 把值对齐到 `PIXEL(=2)` 的整数倍，
而点阵是**逐格**调用的，格边长 `cell` 又恰好是奇数 3：

```
col0 → snap(14) = 14   占 14,15,16
col1 → snap(17) = 18   占 18,19,20   ← 17 空了！
col3 → snap(23) = 24   占 24,25,26   ← 23 空了！
```

逐格对齐让相邻格左右错开 1px，每两格裂一条缝。

**正确做法：原点只对齐一次，之后按整数 `cell` 平移** —— 相邻格必然相接。
（背板本来就是 dpr 倍，整数逻辑坐标天然落在像素中心，根本不需要逐格对齐。）

修完补了断言：同一行/列里相邻两格的空隙**只能是 0（紧挨着）或 ≥ 一整格（有意留白）**，
落在 `(0, cell)` 之间就是裂缝。
这条断言"有牙齿"——把修复回退后它立刻报出 `10 处裂缝，例如 {"at":26,"gap":1}`，
和手测的像素坐标完全对上。

> 顺带一个观察：这个 bug **只在 `cell` 为奇数的机型上出现**。
> 矮安全区机型按钮缩到 24px，`cell = 2` 是偶数，反而没裂缝 ——
> 所以它逃过了所有断言，只在 iPhone 15 Pro 这一档上显形。

| `profile.vol` | 波动强度 0~2 |
| `profile.luck` | 命运 −1（易爆雷）~ +1（易走强） |

### 新闻池条目 `js/data/newspool.js`

```js
news('np_06', 'transport',
  '国际航运运价指数创三年新高',
  '波罗的海干散货指数连续八周上涨……',
  { kind: 'irrelevant', theme: 'bull', truth: true,
    source: '航运日报', credibility: 0.85,
    impact: { drift: 2.8, turns: 2 } });
```

| 字段 | 说明 |
|---|---|
| `sector` | 所属板块，与股票 `sector` 匹配（`macro` = 宏观） |

| `theme` | `bull` / `bear` / `neutral` |

| `impact.drift` | 影响幅度（%）；`irrelevant` 时被忽略 |

`np_06` 就是玩家举例的"船运利好 vs 陆运股"——它 `kind: 'irrelevant'`，
会照常出现在新闻卡上，但对陆运股票的股价**毫无影响**。

> 测试里还带一条**反向自检**（用真年份/真风格词去撞正则，确认能抓到），
> 否则正则写错了会让上面三条断言永远通过 —— 等于没写。

**几个测试手法值得注意**（都踩过坑）：

- `smoketest` 的 `driveFrames()` 必须**手动排空** `requestAnimationFrame` 队列来驱动帧，
  并且要先驱动一帧让 `layout()` 跑过，热区才有内容 —— 否则点到空热区。
- `diag-december` 想抓「界面上真正画了什么字」，必须钩 **`getContext('2d')` 返回的那个 ctx**：
  `widgets.js` 用的是模块级 `ctxRef`（由 `bindContext` 绑定一次），
  给 `render()` 传自己造的 ctx 是抓不到任何 `fillText` 的（会得到空数组）。
- `diag-chart` 用「**同色路径里点数最多的那条**」来区分数据折线与其末端箭头
  （两者颜色相同，只按颜色过滤会把箭头的点混进来）。
- `diag-wavy` 验证「图不会变」时，不能只看 `wavyPath()` 的返回值 ——
  必须**用记录型 ctx 渲染真实场景**，把每次绘制调用序列化成字符串逐条比对，
  才能覆盖"场景层是否引入了额外随机性"这种问题。
  另外 `widgets.js` 用模块级 ctxRef，`_renderChartOverlay()` 内部会调 `panel()`，
  所以测试里**必须 `bindContext(ctx)`**，否则会抛「未绑定 canvas 上下文」。
- **测试里的一次性策略必须可重置**：`balance.mjs` 的 `buyAndHold` 用闭包 `done`
  标记"只买一次"，但闭包是**模块级、只创建一次**的 —— 200 局里只有第 1 局真的买入。
  凡是"跑 N 局"的测试用到了带状态的策略，都要给它一个 `reset()` 并在每局开头调用。
- **过期的测试前提要敢于推翻**：`balance` 里曾有一条"换手应输给定投不卖"，
  看起来天经地义，其实**前提就是错的**（定投仓位天然更轻，牛市必输）。
  继续围绕错误前提调参只会越调越偏 —— 宁可换掉基准，也不要迁就一条错的断言。
- **单例对象在测试里必须 `reset()`**：`DataBus` 是单例（`new DataBus()` 永远返回
  同一个实例），第一版 `diag-levels` 在多个用例里各 `new` 一次，结果
  `usedSeasonIds` 跨用例串场，报出"已用 6 个年景""20 关只去重到 16 个"这类假故障。
  凡是单例 + 累积状态，测试里每个独立场景都要先复位。
- **正则断言要带一条反向自检**：`diag-levels` 断言"关卡文案里不得有年份"，
  但正则本身写错的话这条断言会**永远通过**。所以额外加一条
  `ok(/19\d{2}/.test('1996 · 全民炒股'))` —— 用真年份去撞正则，确认它真的能抓到。
  同理，`diag-levels` 里还断言了"400 次抽卡应覆盖 6 种风格" ——
  正是这条抓出了 `lv_05` 被占位 `style` 压成 flat-only 的 bug。
- **风格/枚举列表不要写死**：`diag-delist` 原本写死 `['bull','bear','flat']`，
  风格扩到 6 种后它**静默漏测了 3 种**（测试还是绿的）。现改为从
  `MARKET_STYLE_KEYS` 派生。
- **`null` 与"未指定"要用哨兵值区分**：见 §2b 的 `'all'` 哨兵 ——
  返回 `null` 会被调用方理解成"没指定，用默认值吧"，兜底值反客为主。
- **测试桩太薄等于没测**：音频那条最初写的是
  `() => ({ play(){}, stop(){}, destroy(){} })` —— 连 `ctx.loop` 和 `ctx.paused`
  都读不到，`loop` 忘了打开、音量忘了设，测试照样全绿。
  现改为 `tools/wx-audio.mjs` 里的可观测桩（真实属性 + 调用日志），各测试共用。
- **断言的形状可能本身就是错的**：`diag-layout` 第一版断言"横幅底边 ≤ 第一张卡片顶边"，
  在 iPhone SE 上失败 —— 但那是**测试错了**：空间不足时横幅本来就该降级成
  悬浮在卡片下方的覆盖层。正确的断言是"横幅不与**任何**卡片相交"。
  断言失败时先问一句"是代码错了，还是我这条断言的形状假设错了"。
- **PyAV 的 plane 缓冲区带对齐填充**（做音频转码时踩到）：
  1024 个采样（真实 2048 字节）返回 `buffer_size = 2112`，
  直接 `bytes(plane)` 每帧多吃 32 个采样。**必须按 `samples × 每采样字节数` 截断**。
  这个 bug 在"断言全绿"里完全看不见 —— 是靠逐秒 RMS 曲线对比才发现的。
  > 一句话：**跨出"断言"这一种验证手段**。曲线、截图、听感，都是断言覆盖不到的。
- **"看起来天经地义"的像素对齐函数要当成有副作用的东西**：`snap()` 不是格式化，
  它会**改变坐标**。点阵逐格 `snap()` 时，奇数 `cell` 会让相邻格错开 1px 裂出缝
  （见 11.8）。凡是"按固定步长重复绘制"的地方，对齐只能做在**起点**，
  不能做在每一次迭代上 —— 否则误差会按步长累积/交替。
- **修完 bug 要把断言"验牙"**：新写的裂缝断言把修复回退后能立刻报出
  `10 处裂缝，例如 {"at":26,"gap":1}`，和手测像素坐标一致 —— 这才算这条断言真的在守。
  同理，`diag-layout` 里那台 `safeTop=100` 的假机型也是为了证明断言有牙齿。
- **同一个 bug 可能只在部分机型上显形**：裂缝只在 `cell` 为奇数的机型出现，
  矮安全区机型（`cell=2`）完全正常 —— 所以它逃过了所有断言。
  **多机型矩阵**是这类 bug 的唯一出口，单机型测试必漏。

### 背景音乐

进游戏即自动循环播放 `audio/bgm.mp3`（60 秒，96kbps，704 KB）。
`js/core/bgm.js` 全程只用一个音频实例，`loop = true`；`main.js` 在首次触摸时兜底拉起播放
（绕开 iOS 首次交互前可能被拦下的问题）。

想**把音频从代码包里摘出去**（省 704 KB），把 `src` 换成远程地址即可：

```js
bgm.init({ src: 'https://your-cdn.example.com/bgm.mp3' });  // 需先配 downloadFile 域名白名单
```

静音接口由 `js/core/audio.js` 统一提供（`audio.toggleMute()` / `audio.setMuted(true)`，
状态写进本地缓存、跨会话保留），它同时管着 BGM 和音效。

### 音效与声音开关

- **点击音效**：`audio/click.wav`（53ms，4.6 KB）。玩家点中任何可交互区域时响一声。
- **声音开关**：**左上角**的小喇叭按钮，就在灵动岛左边的留白处。
  - 🔊 有声 —— 喇叭 + 声波，边框是浅灰
  - 🔇 静音 —— 喇叭变暗 + 红叉，边框变红（一眼能看出当前是静音）
  - 关掉时先响一声再静音；打开时先静音再响一声 —— 两个方向都有听觉反馈
  - 状态跨会话保留，和 BGM 共用同一个开关
