## 数据层重构：固定路径 + 一文件一实体 + 开局随机（05:35）

**波动改为逐回合固定值**（推翻之前的随机漫步方案）：

- 每只股票数据里带 `path` 数组，逐回合写死涨跌幅（%）：`nextPrice = price * (1 + path[turn] / 100)`
- 带 `floor` 字段做价格下限裁剪
- 好处：难度曲线精确可控、可与新闻精确咬合、调试友好
- 代价：玩家可能背走势 → 用「8~12 只股票 × 每只 2~3 条路径」的抽取组合拉开差异

**数据文件组织：一文件一实体**

```
data/
├── index.js          # 注册表
├── stocks/*.json     # 一文件一只（600001.json …）
├── news/*.json       # 一文件一条（n_001.json …）
├── levels/*.json     # 一文件一关
└── comments.js       # 机构评语库
```

**⚠️ 关键技术约束（已澄清）**：微信小游戏**没有读工程源码目录的文件系统能力**。`wx.getFileSystemManager()` 只能操作用户数据目录。所以不能用 `readdir` 遍历，`data/index.js` 必须**显式 import 每个实体**。这是平台硬限制，不是实现偷懒。

**随机机制：每局都随机，局内固定**

开局编排一次（`news/dispatcher.js`）：
```
1. 从关卡 stockPool 抽 1 只标的
2. scriptedNews 按 turn 固定绑定
3. 从 randomNewsPool 抽 M 条填充（M = 总回合数 - 剧情新闻数）
4. 填充新闻随机分配到非剧情回合（排除剧情回合）
5. 结果写入 databus，整局不变
```

**固定路径与新闻的关系**：`最终涨跌幅 = 路径值（固定） + 新闻临时偏移（逐回合衰减）`。两者解耦，路径管难度曲线，新闻管叙事节奏。

**新增 3 条风险**：平台无法读文件夹、路径被玩家背下来、数据文件数量膨胀

**新增文件**：`core/random.js`（随机封装，预留种子接口）、`data/index.js`（注册表）

- 每回合预设 **12 条候选新闻**，一关共 **12 × 12 = 144 条**（原为整关 30~50 条）
- 每条新闻**必须**与三只股票之一关联，新增两个字段：

  - `link`：关联类型 `direct`（直接点名）/ `industry`（行业政策/上下游）/ `macro`（宏观传导）

- 计算公式（三因子加权，保持简单）：
  ```
  score = 走势因子 × 0.5 + 新闻因子 × 0.3 + 随机噪声 × 0.2
  ```

- 新闻因子特殊处理：`truth` 为真则跟随 impact 方向，**为假则反向**
- **假消息不点破**：让评级方向与新闻方向轻微背离，老手能嗅出不协调。这替代了原「暗示型评语」方案，更含蓄

### 2. ⚠️ 发现并修复了一个严重架构缺陷：场景热区在 render() 中注册
**问题**：四个场景（menu/trading/newsflash/result）都把 `addTouch()` 写在 `render()` 里，并且每帧 `this._touches = []` 重建。
后果：① 首帧渲染前无法响应触摸；② 每帧重复分配对象；③ 无法做无头测试。

**修复方案**：在 `Scene` 基类引入 **`layout(w,h)` + `ensureLayout(w,h)` + `invalidateLayout()`** 机制：
- `layout()` 负责算几何 + 注册热区
- `ensureLayout()` 由渲染循环在 `render()` 前调用，仅在**尺寸或 `layoutKey()` 变化**时重建
- `invalidateLayout()` 在选股/改手数/交易/结算后手动调用
- 子类通过覆写 `layoutKey()` 把影响布局的数据纳入缓存键（如 trading 场景纳入 selected / orderLots / ratings.length / 价格 / 持仓）

**关键约束（写给未来的自己）**：**绝不要把 `addTouch()` 写进 `render()`。**

### 3. ⚠️ 发现并修复了一个严重的平衡性 bug：关卡数学上不可通关
通过新增的 `tools/balance.mjs`（6 策略 × 200 局）发现：**所有策略胜率均为 0%**。

- 而通关目标定的是 ¥13,000 —— **数学上不可能达成**
- 且原破产线 ¥900 配 ¥10,000 本金，定投不卖会在第 9~11 月必然破产

**修复**：
1. **重做三只股票路径**，振幅提升到 1.34x~1.50x，并赋予明确"性格"：
   - 茅台：稳健白马（先慢涨→中段回调→后段主升浪）全年 +46.6%
   - 万科：周期地产（上半年拉升→年中打压→年底反弹）全年 +49.8%

   - 新增 `DataBus.isTermOver()` 和 `settleTerm()`
   - 移除 `isGoalReached()`
   - 回合流程从 7 步简化为 6 步（破产优先于到期）

## 破产判定口径修复 + 年末强制平仓（06:24）

### 用户报告
> 「每年底强制平仓，每月的破产判断有问题，可能是买入后账户余额变成负数」

**判断准确。** 写了 `tools/diag-cash.mjs` 专项诊断，3 组场景复现。

### 诊断结论
| 现象 | 真相 |
|---|---|
| 买入后余额变成负数 | **不会** —— `validateBuy` 拦住了，现金从不为负 |
| 每月破产判断有问题 | **确实是** —— 口径错了，不是符号错了 |

### 根因（严重程度被低估）
旧口径：`cash < min(股价) × 100`
→ 玩家**只要买股票**（哪怕只买一手），现金立刻跌破线 → 回合末被判破产。

**这是"惩罚正常买入"的逻辑错误。** 实测数据：
- 修复前：定投不卖 **100% 破产**、跟机构买 71%、反向买差评 99%、首月梭哈 1%
- 修复后：**全部策略 0% 破产**，都能活满 12 个月

用户的直觉（"买入后余额有问题"）直接指向了这个 bug 的核心。

### 三项修复（用户已确认设计）

**① 破产口径：总资产**
```js
// 旧：只看现金 —— 惩罚正常买入
return this.portfolio.cash < lowest * 100;
// 新：现金 + 持仓市值
return this.portfolio.totalAssets(this.priceMap) < lowest * 100;
```
持仓是能卖成钱的，必须计入。新增 `bankruptLine()` 辅助方法。

**② 年末强制平仓**（`Portfolio.liquidateAll(priceMap)`）
- 到期时把所有持仓按市价卖出（含手续费），再用**纯现金**判 win / lose
- 理由：持仓是"账面富贵"，不卖出只是数字；也杜绝"死扛不卖躺过终点"
- 明细写入 `bus.result.liquidation`，结算界面显示「年末平仓」「平仓盈亏」两行
- 空仓到期则 `liquidation = null`，文案显示「年末空仓，无需平仓」

**③ 判定时机**
| 时机 | 判 |
|---|---|
| 买入后 | ❌ 不判（只是把钱换成股票，总资产几乎不变，给玩家整月调整） |
| 卖出后 | ✅ 判（`trading` 发 `afterTrade` 事件 → `main.checkBankrupt()`） |
| 非末回合回合末 | ✅ 判 |
| 末回合 | 先强制平仓 + 收益结算，**到期优先于破产** |

统一入口 `Main.checkBankrupt()`，避免判定逻辑散落。
交易面板新增梭哈预警：`⚠ 买后总资产 ¥x < 破产线 ¥y`（软提示，不硬拦）。
新增 `DataBus.wouldBankruptAfterBuy(code, price, shares)`。

**顺序说明**：到期优先于破产 —— 末日总资产不足一手时，平仓后仍是同一笔钱，
交到期结算按收益判定比简单判破产更准确（玩家可能是亏了但没亏光）。

### ⚠️ 新发现的设计缺口（已告知用户，待决策）
修复后**破产结局实际不可达**。实测 300 局极限换手梭哈（每月全卖全买最贵那只），
最坏总资产仍有 ¥6,851，远超 ¥900 破产线。手续费磨损（万三/最低¥5）太轻。

即：现在只有 win / lose，**没有真正的失败态**。若要恢复压力需重新设计
（提高手续费 / 引入杠杆与追保 / 更激进的路径下行段）。已写入 README「已知设计缺口」。

## 第六轮（走势图加入波动）

- `wavyPath(closes, key, { inner=5, volatility=1, amp=0.012 })`

    因为 0.35 时大涨月份会出现 −0.95 元的夸张深谷

### ★ 本轮最大的技术坑：均值回归周期的相位方向搞反了

**症状**：`balance.mjs` 报「换手梭哈 ¥12223 vs 满仓持有 ¥10000」——
即"每月追最贵那只"的换手策略**跑赢了**买入持有，追高没有被惩罚。

**排查过程（关键：不要猜，要拆分量）**：
1. 先修了一个**测试自身的 bug**：`buyAndHold` 用闭包 `done` 标记只买一次，
   但闭包是模块级只创建一次的 → 200 局里只有第 1 局真买入。给它加 `reset()`。
2. 修完后换手仍赢 → 写 `diag-pricing.mjs`（分位法），显示
   "上月最强"次月平均 **高于**全体 → 确认存在正向动量。
3. 写 `diag-momentum.mjs` 做**受控实验**：把 pathgen 的三个分量
   （大盘 β / 个股周期 α / 白噪声）**分别导出**，各自测"上月→本月自相关"。
   结果：个股 α 分量 **r = +0.158（正！）** —— 它非但没惩罚追高，反而在奖励。

**根因**：**价格是涨幅的积分，涨幅是价格的导数。**
我把 `sin` 直接当作**涨幅**（`cos` 作用于 return），于是价格 ≈ −cos，
涨幅曲线在半个周期内近似一条**平顶** —— 连续几个月都是同一个大正值。
"上月涨得多"因此几乎等价于"下月还涨得多"，妥妥的动量。

**正解**：`sin` 作用于**价格水平**，涨幅取其**一阶差分**（≈cos）：
```js
const dLevel = levelAt(t) - levelAt(t - 1);   // 而非 cos(...) 直接当涨幅
const trendBias = prof.trend * K * 2.0 * dLevel;
```
cos 在一个周期内会**完整地由正转负**，峰值后立刻衰减 → 追高买在拐点后。

**受控实验对照**：
| 指标 | 修复前 | 修复后 |
|---|---|---|
| 个股 α 分量自相关 | **+0.158** | **−0.153** |
| 个股 α σ | 0.64 | 1.74 |
| 最强档 − 最弱档 | +0.25% | **−0.23%** |

**修复后 balance 12/12 全绿**：换手 ¥11903 < 满仓 ¥12171。

### 另一个认知修正：对比基准错了，先入为主
原来断言"换手应输给**定投不卖**"，看似天经地义，其实**前提就是错的** ——
定投每月只买一手、长期趴在现金上，**仓位天然更轻**，牛市里本来就会输给满仓。
正确基准应是**同样满仓但从不换手**的 `buyAndHold`。
改对基准后才暴露真正的 pathgen bug。

### 退市机制（配合熊市关）
`rollDelist()` 确定性判定：熊市 89.4% / 震荡 44.5% / 牛市 11.9% 的局会出现退市；
**一局最多一只**（保留 luck 最低者）；清算价跌到 0.5~1.7 元仙股价；
退市回合落在 3~10（留逃生窗口）。持仓被 `liquidateCode` 强制清算。

### 复用要点（第八轮，最高优先级）
1. **"整体指标正常但策略失衡"必须拆分量定位** —— 写受控实验把各分量单独导出测自相关，
   比盯着一个总数调参高效 10 倍。
2. **给"涨跌幅"做周期调制时，sin 要作用于"价格水平"再取差分，绝不能直接作用于涨幅** ——
   否则得到的是平顶（plateau）而非峰谷，反而制造动量。
3. **跑 N 局的测试里，带状态的策略必须有 `reset()` 并在每局开头调用** ——
   模块级闭包只创建一次，否则只有第一局真的执行。
4. **过期的测试前提要敢于推翻** —— 围绕错误前提调参只会越调越偏。
   宁可换掉对比基准，也不要迁就一条错的断言。
5. **数据层按"实体"组织还是按"属性（板块）"组织，决定了随机组合能不能成立** ——
   想让"随机抽 3 只 + 新闻跟着变"成立，新闻必须挂在**板块**上而非具体股票上。
6. **确定性 ≠ 无随机性**：随机性只放在"开局抽签"（seedKey），
   生成路径是纯函数 —— 于是"每局不同"与"局内恒定（走势图不变）"同时成立。

## 第八轮续（印花税 + 一条被推翻的断言）

### 起因

### 处置一：印花税（真实规则 + 强化信号）
`order.js` 原本两边都是佣金万三/最低¥5 → 一次全换手成本仅 ¥12（0.12%），
一年 1.4%，**惩罚形同虚设**。
改为**卖出加收千一印花税**（A 股真实规则）：`calcFee(amount, side)` 新增 `side` 参数。
`portfolio.js` 的 buy/sell 分别传 `'buy'`/`'sell'`。

### 处置二：测试统计化
- 局数 200 → **600**
- 时间种子 → **固定种子** `setSeed('balance-v1')`
  （时间种子导致每次均值都不同，无法区分"代码坏了"还是"运气差"）

### ★ 处置三：断言被推翻（最重要）
即便 600 局 + 印花税，**跨 5 个固定种子测，换手仍 2/5 反超满仓持有**。

**根因是设计本身**：为防"买最贵那只必胜"，pathgen 刻意让
`basePrice` 与 `trend` 完全不相关（r≈0.04）。
既然价格高低不携带未来收益信息，"买最贵"与"买最便宜"就是**同期望**的随机选择 ——
换手唯一真实代价是手续费（~2%/年），**落在年度收益 ±20% 噪声里，注定测不出显著差异**。

**改法**：断言从「收益更低」（统计上不成立）改为「**成本更高**」（确定性成立）：
- `churnR.avgFriction > holdR.avgFriction * 5` → 实测 ¥237 vs ¥22（10.8 倍）✓
- `churnR.avgFriction / 10000 >= 0.015` → 实测 2.37% ✓
- `holdR.avgTrades <= 2.5` → 实测 2.0 笔 ✓

跨 **7 个种子全部通过**。

**这是本轮最普适的一课**：
> **断言要选"确定性成立"的性质，而不是"看起来该成立"的统计关系。**
> 当一个断言时绿时红，先问"这是噪声，还是现象本身不存在" —— 后者更常见。

### 测试计数更新
selftest 253 → **257**（+4 条手续费/印花税断言）；balance 12 → **14** 条断言。

### 复用要点（第八轮续）
1. **交易类游戏的手续费要"双边不对称"** —— 真实 A 股卖出含千一印花税；
   对称的万三成本太轻，高频交易惩罚不出来。
2. **跑 N 局的统计测试必须用固定种子**，否则无法区分代码回归与随机波动。
3. **两个高方差均值做硬比较前，先估算标准误差** —— 差异不显著就别写断言。
4. **当一条"天经地义"的断言反复失败时，要怀疑的不是参数，而是前提。**
   本次前提（"追高会被惩罚"）在设计上就不成立。
5. **改用"确定性度量"替代"统计度量"**：本次用"交易成本"替代"资产高低"。

但年景内部 3 股 6 新闻是精心配好的（行业不重复、每股至少一条对口新闻），
于是每个年景像一个"写好的小剧本"，不是纯随机拼盘。

### ★ 本轮四个真实 bug / 错误判据

**① `flat` 被写成了一个"伪装的熊市"**
扩风格时 `flat.marketBias` 仍是 v3 的 0.2 —— 但那个 0.2 是**配合 `trendScale = 2.6` 标定**的
（v3 的震荡风格复用了牛市分支的 trendScale）。trendScale 降到 0.2 后，失去趋势红利的
0.2 撑不住，实测年化 **−15.87%**，掉到 `calmFlat`（−1.79%）下面，单调性被打破。
→ 修：`flat.marketBias` 提到 **1.4**，实测 **+7.05%**。
→ **教训：参数是成组标定的，拆开其中一个必然失衡。**

**② 三套被推翻的统计判据（本项目最有价值的一段教训）**
为证明"买最贵的没有优势"，我换了三套判据，前两套都错：
1. ❌ `corr(basePrice, trend) ≈ 0` —— 价格档位天然与趋势相关（贵股本就是长期走强的结果），
   优化器为压到 0 给出荒谬定价（地产 28 元、电力 4 元）
2. ❌ `买贵优势 < 0.5%/年` —— 0.5% 是拍脑袋的阈值，无任何统计依据
3. ❌ 拿均值差去比**单路径 σ（48%）** —— 该比的是**均值标准误 SE = σ/√N = 1.81%**，差一个数量级
→ **正解：排列检验**。把 34 个价格标签随机重排 40 次构造零分布，
   实测 1.42%/年 落在 `[−7.34%, +5.89%]` 的第 **63 百分位** → 与随机分配无法区分。
   不需要任何分布假设，也不需要拍阈值。

**③ 真正的缺陷是 `luck` 与价格的隐藏关联（不是相关系数）**
贵的股票恰好都 `luck` 为正、便宜的都 `luck` 为负（赤河酒业/启辰新能/瑞和银行 vs 恒泰置业/佳选食品/长风钢铁）。
→ **分量消融实验**证实：把 `luck` 全置零，优势立刻翻转为 **−3.47%**。
→ 我先走了错路：**按价格重排 `luck`**（便宜给好运）→ 矫枉过正到 **−7.92%**，
   且因价格序已隐含趋势序，`corr(price, trend)` 仍是 +0.41，只是把问题从 luck 挪到 trend。
→ 正解：**反过来求解价格**（luck 不动），重排定价把 `corr(price, luck)` 从 0.26 压到 0.23。

**④ ★ `pool: null` 被占位 `style` 静默破坏（最隐蔽的一个）**
`lv_05` 自称"没有剧本"，`pool: null` 表示全放开，但它还有一句 `style: 'flat'` 作兜底占位值。
而 `composeGame` 早期的筛选顺序是**先 `style` 再 `styles`** ——
那句占位的 `'flat'` 把"全放开"压成「只能抽 flat 年景」，**400 次抽卡全部 flat**。
还有隐蔽的一层：`poolOfLevel()` 对全放开返回 `null`，而 `null` 在调用方看来
等于"没指定，那我用 `level.style` 吧" —— **兜底值反客为主**。
→ 修（两处缺一不可）：
  (a) `poolOfLevel()` 对全放开返回**哨兵值 `'all'`** 而非 `null`
  (b) 筛选优先级改为 **`styles`（池）> `style`（单值）**，并识别 `'all'`
→ 是被 `diag-levels` 的"400 次应覆盖 6 种风格"这条断言抓出来的。

### ★ 两个被我写反/写死的测试
- `diag-delist` 断言"小牛退市率高于大牛"，实测**恰好相反**（大牛 13.6% > 小牛 8.8%）——
  `bull` 中枢更高但 `marketVol`（3.4）与 `crashChance`（3.5%）也更高，
  **上行更猛的市场波动也更大，踩雷概率反而略高**。错的是断言，不是数据。
- `diag-levels` 第一版在多个用例里各 `new DataBus()`，但 `DataBus` 是**单例**
  （`new` 永远返回同一实例）→ `usedSeasonIds` 跨用例串场，
  报出"已用 6 个年景""20 关只去重到 16 个"等**假故障**。
  → 单例 + 累积状态的测试，每个独立场景必须先 `reset()`。

### 设计决策记录
- **年景用 `season()` 工厂 + import 期 throw**（而非只在 `validateData()` 里列错误）——
  立刻抓到两处我手写的数据错：`y04` 材料写两次、`y18` 能源写两次，
  **在 import 阶段就报错**，根本没机会变成静默运行时异常。
- **`poolOfLevel` 返回 `'all'` 而不是 `null`** —— 用显式哨兵把"我明确要全放开"
  与"我没说"区分开。
- **年景池耗尽时复用年景，而非退化到 legacy 抽股路径** ——
  保住"3 股 + 6 条专属新闻"的结构。20 ÷ 5 = 4，可连玩 4 轮（20 关）不重样，
  第 21 关起复用是**刻意设计**，已在代码与 README 里写明。
- **关卡难度靠"市场可读性逐关变差"爬升**（单一风格 → 反向 → 中性 → 混合 → 全放开），
  而不是数值加码。

### 复用要点（第九轮，最高优先级）
1. **想证明"某效应不存在"时，别拍阈值、别拿 σ 当尺子 —— 做排列检验。**
   它不需要任何分布假设，结论是"与随机无法区分"而不是"小于某个我编出来的数"。
2. **"整体指标正常但策略失衡"必须拆分量定位** —— 分量消融实验（把某字段置零看优势翻转）
   比调相关系数高效得多，而且能指出**真正**的致因。
3. **`null` 与"未指定"在 JS 里长得一样，要显式哨兵值** ——
   否则兜底默认值会静默覆盖设计意图，而且测试很难发现。
4. **枚举列表不要在测试里写死** —— 扩枚举时写死的测试会**静默漏测**（还是绿的）。
   从单一来源（`MARKET_STYLE_KEYS`）派生。
5. **正则断言要配一条反向自检** —— 断言"文案不得含年份"时，
   额外用真年份去撞正则，确认它真能抓到。否则正则写错会让断言永远通过。
6. **参数是成组标定的** —— 改 `pathgen` 任何字段后先跑 `diag-styles`（秒级受控实验）
   看那张表，再跑 `balance`（分钟级）。直接跑 balance 只知道坏了，不知道哪坏了。
7. **单例对象在测试里必须 `reset()`** —— 否则状态跨用例串场，产生假故障。
8. **数据校验放在构造期（import 期 throw）比放在启动期（validate 列错误）更早暴露问题** ——
   数据一写错就炸，连运行都到不了。
