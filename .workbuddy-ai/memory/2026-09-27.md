## 第十轮：可读性改版（字号放大 / 灵动岛安全区 / 自适应纵向节奏）

**起因**：玩家反馈「字体可以稍微调大点吗？布局有点紧凑，苹果灵动岛有遮挡，可以在上方留出点空隙吗？」

### 一、新增 `js/styles/layout.js` —— 安全区单一来源

- `setSafeArea(info)` 由 `Renderer._setup()` 调用，从 `wx.getSystemInfoSync().safeArea` 读 top/bottom。
- `safeTop()` / `contentTop()` / `safeBottom()` / `contentBottom(h)`。
- **★ `safeTop()` 自带下限 `MIN_TOP = 24`，不依赖 `setSafeArea` 是否被调用过** ——
  这样测试里直接 `new TradingScene(bus)`（没有 Renderer）也能得到一致的留白。
  如果只在 setter 里夹下限，standalone 场景会退化成 0，测试与真机行为就不一致了。
- `safeArea.top` 缺失时回退到 `statusBarHeight`。

### 二、字号整体放大约 20%

`xs 10→12, sm 12→14, md 14→16, lg 18→20, xl 24→28, xxl 32→38`（保持偶数）。
另加 `shadowOffset(size)`：≥18px 用 2px 投影，否则 1px —— 字号变大后 1px 投影几乎看不见，
"点阵厚度感"会丢。

### 三、交易场景：`tradeFlow()` 让 layout() 与 render() 同源

原先两处各自累加一遍纵向 y，改字号时极易算歪。现在统一由 `tradeFlow(w,h,ratingCount,delistEvent)`
产出全部几何（卡片 / 评级 / 操作区 / 下月按钮 / 横幅）。

自适应策略（`solveHeights`）：
1. 空间富余 → 先放宽间隙（8 → 最多 24）
2. 仍富余 → 长高卡片（84 → 最多 108）
3. 不足 → 依次收紧：间隙（最低 4）→ 操作面板（最低 148）→ 卡片（最低 80）

`minCardH = 80` 是硬下限：再矮，"走势图"按钮（锚在卡片底部）就会撞上右对齐的涨跌幅文字。

### 五、★ 走势图折线冲出面板（横盘股必现）

`lineChart` 的 `toY` 是纯线性外推、不做夹取；而交易场景传的 `min/max` 只按**月度收盘价**算
（原注释写着"不让抖动撑大纵轴"）。于是当全年振幅很小时（横盘股，如 27.64~28.00），
月内抖动幅度（`segAmp = scale * (0.012 + span/scale*0.18)` ≈ 0.35）**远大于全年振幅 0.36**，
折线被外推直接冲出面板。

两处都修：
- `chart.js`：`toY` 夹在 `[plotY, plotY+plotH]` —— 图表库不能假设调用方永远给对范围。
- `trading.js`：纵轴范围改取**实际画出来的那条路径**的极值；"最高/最低"仍报真实收盘价。

发现方式：**把无头渲染的绘制指令导出成 HTML 在浏览器重放**（`tools/shot.mjs`），
肉眼一看就发现了 —— 测试全绿完全掩盖了这个 bug。

## 音频素材调研（sonilo_music_*.m4a）

- 编码 **AAC (mp4a) / 立体声 / 16bit / 44100Hz** —— 格式本身 iOS + Android 双端都支持。
- ⚠️ 但容器是**分片 MP4（fMP4）**：`moov` 里 `mvhd` 时长 = 0，`mvex` 只有 `trex` 没有 `mehd`，
  正文是 **2585 个 `moof`+`mdat` 分片**。**全文件没有声明总时长** → `audio.duration` 会是 0，
  循环/seek 行为不可靠，iOS 上风险更高。建议先重封装（`-c copy`，不重编码）成标准 M4A/MP3。
- 大小 **2.15 MB = 主包 4MB 上限的 54%** → 不宜进主包；应放分包、或用 CDN/云文件 ID 远程播放。

## 第十一轮：背景音乐接入 + 文档补记

**需求**：「这首曲子能放进游戏里循环播放吗」→「纯粹的背景音乐，循环播放就行」。

### 一、转码（`tools/transcode_bgm.py`，PyAV）

系统里没有任何 `ffmpeg`，改用 **PyAV**（自带 ffmpeg 库，纯 wheel）。
装进隔离 venv：`C:/Users/plume/.workbuddy-ai/binaries/python/envs/default`。

- 解码 → 掐首尾静音（实测首 20ms / 尾 24ms）→ 重编码。
- 结果：**2205 KB → 704 KB（31.9%）**，60.003s，96 kbps 立体声 44.1kHz，带 Xing 头。
- 顺带把 fMP4 摊平成普通 MP3，摆脱 `mvhd.duration = 0` 的兼容风险。
- 原曲本身**带收尾淡出**（最后 1 秒 −30 dB），所以循环点是"淡出→重来"，不是无缝。
- libmp3lame 只接受 **planar** 采样格式（`s32p`/`fltp`/`s16p`）；用 planar 的好处是
  裁剪可以按声道直接切字节。

### 二、★ PyAV plane 缓冲区带对齐填充（最值钱的一个坑）

```
1024 采样的 s16 平面 → 真实数据 2048 字节
但 plane.buffer_size = 2112  ← 多 64 字节
```

直接 `bytes(plane)` 每帧多吃 **32 个采样**：2585 帧累计多出约 **8.2 万样本**，
既把时长拉长 1.83 秒，**又把填充字节当音频样本写进输出**（每 23ms 插一段杂音）。

正确做法：按 `samples × 每采样字节数` 截断。

**发现方式**：断言全绿，是靠**逐秒 RMS 曲线对比**（源 vs 输出）才发现的 ——
曲线逐秒对齐才算证明转码没引入失真。第一次跑出来源 61.899s / 输出 63.578s 就露馅了。

## 第十二轮：按钮点击音效 + 左上角声音开关

需求：「能不能下载个合适的按钮点击音效，并且在左上角加个关闭声音的按钮，
就在为了隔开灵动岛的旁边。」

### 一、点击音效 `audio/click.wav`

- **「合适」先量化再挑**：拉了 40 个候选（36 Mixkit MP3 + 4 OpenGameArt CC0 WAV），
  按 有效时长 / 起始延迟 / 峰值电平 / 衰减干净度 打分。
  Mixkit 全部不合格（时长 ~1.1s、尾部 ~0.85s 静音、编码延迟不可控）。
  选 CC0 `qubodup-click2.wav`（55ms、零起始静音、峰值 −7.1dB、单调衰减）。
- 成品：53.1ms / 44100Hz / 单声道 16bit / 4,728B / 起始延迟 0.39ms / −3.0 dBFS。
- 加工脚本 `tools/make_sfx.py`：降混单声道 → 掐静音 → 归一 → 1.5ms 淡入淡出 → 复测起始延迟。
- **授权**：CC0 1.0（可商用）。临时候选目录已清理，来源记在 README §11.5。

### 二、为什么音效用 WAV 而不是 MP3（反直觉，有实测）

| | 起始延迟 | 体积 |
|---|---|---|
| MP3 (LAME) | **0.00ms** | 1,088B |
| WAV | 0.39ms | 4,728B |

MP3 反而更准（LAME 写 Xing 头，解码器会剥掉编码器延迟）。
但官方文档明确「两个平台完全支持的音频格式有 mp3、aac、wav」→
WAV 是唯一不用赌解码器行为的。**4.6KB 换"确定性"，值。**

官方另一条常被忽略的规则：**「对于相同的音效，应该复用已有的音频实例」** →
`playClick()` 用 3 实例池轮转，复用前先 `stop()` 归零（否则连点会叠在一起）。

### 三、静音归属重构：bgm.js → audio.js

### 五、★★ 本轮最重要的坑：点阵逐格 `snap()` 会把图标画裂

**这个 bug 是"看"出来的**：12 倍放大截图后发现图标上有 3 条 1px 黑缝。

根因：`snap(v) = Math.round(v / PIXEL) * PIXEL`（PIXEL=2）把值对齐到偶数，
而点阵是**逐格**调用的，`cell` 又恰好是奇数 3：
```
col0 → snap(14) = 14  占 14,15,16
col1 → snap(17) = 18  占 18,19,20   ← 17 空了！
col3 → snap(23) = 24  占 24,25,26   ← 23 空了！
```
相邻格左右错开 1px，每两格裂一条缝。手测像素坐标 x=56/62/68 完全对上。

**修法：原点只对齐一次，之后按整数 `cell` 平移。**
（背板本就是 dpr 倍，整数逻辑坐标天然落在像素中心，根本不需要逐格对齐。）

**断言化**：同行/列相邻两格的空隙只能是 0（紧挨着）或 ≥ 一整格（有意留白），
落在 (0, cell) 之间就是裂缝。**并且"验了牙"**：把修复回退后立刻报
`10 处裂缝，例如 {"at":26,"gap":1}`。

> ⚠️ 该 bug **只在 `cell` 为奇数的机型出现**（矮安全区机型 `cell=2` 正常），
> 所以它逃过了所有断言，只在 iPhone 15 Pro 这一档显形。
> **单机型测试必漏 —— 多机型矩阵是这类 bug 的唯一出口。**

**推广**：凡是"按固定步长重复绘制"的地方，对齐只能做在**起点**，
不能做在每一次迭代上，否则误差会按步长累积/交替。

## 第十三轮：价格波动 / 机构评级 / 消息 —— 链路排查

玩家原话：「最后排查下，价格波动，机构评级和消息，我觉得机构评级有点太准了，
应该适当减少下机构评级的准确度，比如市场剧烈波动的时候虽然看多，但是受到整体趋势的影响
还是下跌，再比如，公司财务造假暴雷问题。」

### 一、先量化"太准"有多准

新建 `tools/diag-rating.mjs`（升格为第 18 个套件）。**基线（改之前）**：

| 指标 | 基线 |
|---|---|
| 看多档下月上涨 | **65.7%** |
| 看空档下月下跌 | **66.6%** |
| IC | **0.307** |
| 档位极差 | **+7.22%** |
| 暴雷前一月看空比例 | 53.9%（基准 35.8%，高出 18pp） |

**玩家的直觉完全正确。**

### 二、★ 根因：辛普森悖论

| | IC |
|---|---|
| 分风格（6 种各自） | **−0.03 … +0.03**（≈0，没有选股能力） |
| 合并全部风格 | **0.307** |

大盘暴涨月"看多档"命中率 **97.8%**、"看空档" **0.8%**；大盘暴跌月"看多档" **25.2%**。
**评级是个大盘方向指示器** —— 它泄漏的是本该隐藏的市场风格（关卡设计明令不告诉玩家）。
"显得准"的全部来源是**月度收益的正自相关**（动量），而评级用的是**已实现**的涨跌幅。

### 三、三处改动

| # | 改动 | 效果 |
|---|---|---|
| ① | 走势因子改**相对强弱** `(change − 三股均值)/4` | IC 0.307 → 0.036；看多 65.7% → 50.3% |
| ② | `pressured` 由"取负"改"**取正**"（机构跟着标题看多） | 暴雷前看空 53.9% → 38.2%（基准 35.9%） |
| ③ | 权重 `相对强弱 0.30 / 新闻 0.10 / 噪声 0.60` | 见下 |

玩家给的两个例子**现在都成立**：
- 例① 大盘暴跌月"看多档"下月真的涨只有 **12.5%**，基准率 12.2% → **超额 +0.3pp**（零信息）
- 例② 财务造假暴雷，机构看不穿（跟着标题看多）

### 四、★★ 最重要的方法论纠正：判据用错了

市场本身有动量溢价。三条策略月均收益：

| 策略 | 月均 |
|---|---|
| 等权三只 | −2.388% |
| **跟本月涨幅最高**（玩家自己看行情就能跑） | **−1.831%** |
| 跟评级全仓 | −1.874% |

「跟评级 − 等权」= +0.514% 看着像作弊，但「跟动量 − 等权」= +0.557% ——
**玩家不用评级也能拿到**。真正的判据：

```
★ 跟评级 − 跟动量 = −0.043% / 月   ⇒ 评级没有任何独占信息
```

> **为什么**：`marketChange` 是三只股票的**均值**，给三只股票减**同一个**常数
> **不改变排序**。所以评级的排序天然等于"本月涨幅排序"（排序一致率 70.9%），
> 而"本月涨幅"在 `trading.js` 的股票卡片上（`changeMap`）玩家本来就看得见。
> **刻意接受**：宁可让评级"只是在复述公开行情"，也不能让它当预言机。

**推广**：判断任何"提示型 UI 是否作弊"，都不能只看"跟着它做赚不赚"，
必须减去"玩家用公开信息自己就能做到的那份收益"。
**信息价值 = 独占信息，不是总收益。**

### 五、★ 顺链路挖出的两个静默缺陷

| 缺陷 | 症状 | 修法 |
|---|---|---|
| **新闻对价格零影响** | `simulator.applyNews` 定义好但**从未被调用**；`effects` 恒空、`newsChange` 恒 0.000 | `nextTurn()` 补 `applyNews(this.news)` |
| **退市当月上报涨跌幅矛盾** | 价格 ¥8.5 → ¥1.2（−85.9%），上报只有 −0.8% | 改用价格转移算的 `actualChange` |

缺陷①的后果远超"少个效果"：`pressured` 机制从未生效，
核心爽点"从评级与新闻背离里嗅出假消息"**根本没有可背离的对象**。
两个缺陷都**不抛异常、不打日志**，只能靠自己写探针把中间量打出来。

**教训：函数存在 ≠ 函数被调用。** 静态检查、类型检查、只测函数本身的单测都抓不到。

### 六、为什么不继续加噪声

0.68 / 0.79 会让"看多档下月上涨"掉到 50% 以下（49.4% / 48.9%）——
评级从"不准"变成"**反着准**"，玩家会发现反着做更赚，那是另一种更糟的作弊。
0.60 是"抛硬币且不倒挂"。

新闻权重也**不能压到 0**，否则评级与新闻永不背离，核心爽点消失。

### 七、测试口径的连锁修正

噪声占六成后，**任何断言"总分"的测试都会误报**。修了 4 处：

| 测试 | 原 | 新 |
|---|---|---|
| `selftest` 评级组 | `upBull >= 24`（总分） | 断言 `parts.trend`（确定性），总分放宽到 22 |
| `selftest` 假消息组 | `truthPos/fakeNeg >= 24` | `newsOpposite === 40` + `NEWS < NOISE×0.5` + 总分倾向 < 78% |
| `selftest` 相对强弱组 | `relOk === 40` | `trendOrder === 40` + `relOk >= 27`（理论 35，12.5% 翻盘**是设计**） |
| `diag-rating` 判据 | 极差 > 1.5% 报警 | 极差放宽到 4% 只当哨兵；主判据改「评级 − 动量 > 0.15%」 |

> **教训**：断言"总分的测试"会在**调权重**时集体误报。
> 必须把确定性因子（`parts`）暴露出来单独断言，权重才能自由调整。

## 第十四轮 · 连闯（多关接力）

### 一、需求

> 每关结束可以选择自动进入下一关还是返回主界面，进入下一关延续上一关结束时的资金状态。
> 五关结束后可以选择继续，将再来五关。也可以选择退市结算。注意，每关不要重复相同的股票，
> 股票数量要是 3 的倍数，避免最后一关只剩 1-2 只股票的情况。

### 二、★ 最大决策：年景层撑不起"无限连闯"

`composeGame` + `excludeSeasons` 的路子直接算崩了：20 个年景 × 3 只 = 60 个股票位，
池子只有 36 只 → 平均每只出现 1.67 次，必然重叠。实测贪心选"与已选年景完全不重叠"
的最大集合（2000 次）：6 关 17% / 7 关 51% / 8 关 32% —— **最多 ~7 关就撞车**。

→ 新增 `composeFreshLevel()`：绕过年景，直接从 `STOCK_POOL` 抽 3 只（带 `excludeStocks`）。
年景层（`composeGame`）保留给受控实验（`diag-rating` / `diag-styles` 显式传 `{ season }`）。

> **教训**：中间层会悄悄绑定上层假设。"5 关一局"下好用的年景层，
> 换成"无限连闯"直接失效。改上层规模时要**重新验算中间层容量**，不能想当然复用。

### 三、★ 何时允许股票复用：轮界补货

三种做法都实现并实测：

| 做法 | 结果 |
|---|---|
| 每轮清空 | 第 6 关立刻撞第 1 关（太保守，一轮只用 15/36） |
| 用完才清（剩<3） | 能连闯 12 关，但清空点落在**第 13 关**，轮界在 11 关 → 第 3 轮内部撞车 |
| **轮界补货** | 轮界检查 `STOCK_POOL.length - usedStockCodes.length < 3 * LEVEL_COUNT`，不够才清 |

36 只实测：第 1 轮用 15 剩 21（不清）→ 第 2 轮用 15 剩 6（清）→ 第 3 轮。
**连闯 10 关零重复**，且每轮内部绝对不重样。

### 四、"股票数量是 3 的倍数"的因果链

```
池子不是 3 的倍数 → 清空点落在关卡中间 → 某关剩余候选 < 3
                 → 抽不满 3 只 → 最后一关只剩 1-2 只
```

为此池子 **34 → 36**（12 行业 × 3）：`901103 沃丰饲料`（agriculture）、`901203 翰墨出版`（media）。

### 五、★ 共享对象污染

`LEVELS` 是模块级共享数组。最初把"下一关资金"写回 `level.initCash` → 第 1 关本金被
永久污染且跨局残留。改为 `DataBus.initCash` 作唯一真源，`finish()`/`settleTerm()`
一律读 `this.initCash`。`smoketest` 加了 `level.initCash === 10000` 守卫。

### 六、★ 版面：两个按钮并排（不是堆叠）

堆叠要占 `2×52+12 = 116px`，而轮末比普通关多两行（56px）+ 熊市多一行退市记录
→ 走势图高度算成**负数**、整块消失。并排只占 52px。
走势图三级降级（≥96 → 96 / ≥52 → room / 否则 0），且**标题+图例+折线整块开关**。

### 七、★ 只有截图才能发现的坑

`shot.mjs` 快进到轮末时直接 `bus.settleTerm()` 而**不跑那 12 个月**
→ simulator 历史只有 1 个点 → `seriesCount = 0` → 轮末的走势图整块不画。
**看起来像版面退化，其实是快进方式不真实。** 修法：老老实实 `nextTurn() + settle()`。

> **教训**：让测试"跳过流程"会改变被测状态本身。

### 八、退市结算口径

`finalSettle()`：`init` = 第 1 关本金、`total` = 末关期末、`turns` = **各关之和**、
`levels` = 连闯关数、`isFinal = true`。为此 `finish()` 往 `runResults` 补了 `turns`。
**必须关 `runMode`**（否则 `actionsOf` 还会摆出"进入下一关"）；
`canContinue()` 与 `startNextLevel()` 都加了 `result.isFinal` 守卫（双保险）。

|---|---|
| `diag-levels` | 65 → **192**（新增 `[7] 起点推导与退市结算`） |
| `diag-layout` | 292 → **421**（新增 `[5] 结算场景版面`，3 机型 × 4 状态） |
